# 读取带有个人媒体偏好的聊天

[English](guide.md) | 中文

## 变更

图片和视频个人偏好独立于登录凭据保存，按后台 URL 和账号 ID 隔离。新聊天提交通过必需的 `media/request-selection` Session 事件捕获本次选择。修改偏好只影响后续提交，已受理任务及其恢复保留原型号与参数。真人本次明确要求优先于已保存默认，非 H3 的费用确认仍然必需。

Session 格式版本保持不变。新版读取器可以读取没有该事件的已有聊天。旧版读取器遇到该未知必需事件时拒绝读取，避免静默丢弃会影响生成和计费的选择。清空已保存偏好不会删除聊天中已提交的事件。[持久化确认记录](../../../persistence-changes/2026-11-01-chat-media-preferences.zh.md)说明两个方向的兼容性。

## 迁移

1. 保留现有 Session 目录和账号文件，无需手动迁移或重置凭据。
2. 个人媒体选择被捕获后，使用新版客户端打开该聊天。切换旧版前保留可用的新版；旧版仍可使用不包含此必需事件的独立聊天。
3. 在聊天输入框下方打开图片或视频选项，核对当前账号可用型号并保存静态参数。选择“跟随平台”可清空该类别后续偏好。已停用的型号需要改选可用型号或清空偏好，不会自动换成另一收费型号。
4. 更新媒体工具调用方，使用 `list_image_models` 或 `list_video_models` 返回的实际 `default_model_id` 和 `selected_parameters`。当 `default_error_code` 表示规格尚未补齐时，这两个字段仍然保留。遇到 `MEDIA_MODEL_MISMATCH` 时按该型号重新准备参数，不要反复重试另一型号的参数。显示别名 `mt-MiniMax-H3` 仍使用原 `MiniMax-H3` 提交 ID，与 `ycapi-minimax-h3` 是不同渠道。
5. 确认后续独立请求使用已保存选择，已受理生成仍保留原任务。仅保存型号而该型号有多个完整规格时，提交前仍须明确唯一规格。
