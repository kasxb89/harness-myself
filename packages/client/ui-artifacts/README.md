# @deepseek-ai/dsh-client-ui-artifacts

English | [中文](README.zh.md)

## Summary

Find files in two ranges: the Artifacts library shows configured and retained output directories; Workspace files browses a registered workspace directory. Both show the actual Host path and support previews and file management. Workspace files includes existing files as well as newly created ones; the page does not claim that every file was generated by a Session.

## Use this package

Mount `@deepseek-ai/dsh-client-ui-artifacts` in the browser roster with the slot and locale services. Pair it with [artifacts-index](../../deliverables/artifacts-index/README.md) for authenticated file access and the workspace registry for workspace choices. This package has no configuration fields.

The Artifacts library reads the managed output roots and retains its save-directory settings. The directory dialog accepts an existing absolute path and offers the native folder picker when available. Saving a directory affects future generation, keeps older files visible, and does not move them. Selecting a workspace does not change this preference or add its root to the saved output roots.

Workspace files selects the registered workspace matching the current Session when available. Without a match, choose a workspace explicitly. Open directories as needed and use breadcrumbs to move back; search applies to the current directory together with the type filter. The selected workspace and full file path identify where a file actually resides, including files created by shell commands in a non-Git workspace. Removing a workspace revokes access through this browser.

Select a file in either range to preview, rename or move it to the recovery area. File changes use the selected size and modification time; a changed or conflicting file requires review instead of overwriting. Restore entries from the recovery area, including after reopening the app. Workspace-file recovery requires its original canonical workspace directory to be registered again. Destructive actions require confirmation; uncertain mutation outcomes require refreshing before trying again. When the serving Host provides the capability, the page offers revealing the selected file in that Host's file manager.

Images, video and audio use browser media elements; supported text, code and spreadsheet kinds use a text preview. Embedded raw previews are sandboxed. Read failures retain previous data with a visible retry. Refresh reconciles the selected file with the current listing and ignores obsolete responses.

## Understand the implementation

<details>
<summary>Implementation internals — click to expand</summary>

The browser plugin contributes the `artifacts` main panel and its sidebar entry through declaration-aware slot registrations. [`ArtifactsPage.tsx`](src/client/ArtifactsPage.tsx) owns the selected range, workspace, current directory, search, filters, selection and management dialogs. Injected callbacks own HTTP operations and optional native directory and file actions. Its injected dictionary supplies the page copy; the Host half is empty.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

These limits describe the package’s current behavior and dependencies.

- Listings refresh on mount or user request; the page has no filesystem subscription.
- Workspace directories load on demand. Search covers the current directory, not an unseen recursive tree or every registered workspace. Hidden, dependency and private artifact-state directories are omitted, as are subdirectories with `:`, `\` or control characters in their names.
- Workspace files is a file browser, not a complete history of generated outputs. Existing source files remain workspace files; neither a successful `present` call nor Git tracking is required for them to appear.
- Document, slide, archive and other unsupported kinds show file information rather than a converted preview.
- Text previews above 256 KiB, or failed text reads, fall back to the raw URL in a frame; format rendering depends on the browser.
- Search, filtering and selection belong to the mounted page and are not persisted. Directory preferences and recovery records belong to the Host.
- Renaming or recycling does not rewrite old chat links. Recovery retains file bytes and does not free their disk space. Unsupported filesystems cannot safely rename or recycle files.
- Paths and native file actions refer to the serving Host. A remote Host’s files are not files on the browser’s local machine; workspace filesystem mappings unsupported by that Host are refused.
