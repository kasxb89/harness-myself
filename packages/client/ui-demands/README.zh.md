# @deepseek-ai/dsh-client-ui-demands

[English](README.md) | 中文

<a id="summary"></a>
## 概述

侧边栏「需求发布」包含「需求广场」「论坛中心」「案例展示」「官方定制」四个标签页。需求广场默认展示审核通过的公开需求；「我的需求」保留当前用户的草稿、已发布需求、接单和私密历史。论坛中心支持公开帖子、回复、Unicode 表情和点赞；后台明确提供能力时，启用图片附件、个人记录、通知与论坛昵称。案例展示按分类呈现明确配置的图片与视频，并保留素材来源。官方定制展示平台服务目录，并保留与真人工程师的私密会话。发布、审核、接单、分派、权限和处理状态由后台管理。

## 使用本包

浏览器插件与 slots、locale、layout 和既有 Credits 账号数据源一起装配，Web 配置已包含本包。本地载体设置 `enabled` 默认开启；未登录、加载中、服务不可用或后台停用时，侧边栏入口仍然显示。显式设为 false 会关闭本地传输并隐藏该入口。后台的 `config.enabled` 决定是否接受新需求。旧后台没有需求接口时显示不可用。服务关闭后保留已读取的历史，并以服务器当前权限为准，不虚构工程师，也不删除旧需求。需求广场、论坛中心、案例展示与官方定制保持独立页签；受账号保护的列表、聊天、上传和业务写入仍须登录。

Host 通过结构化页面启动数据发布声明为公开的载体设置和案例目录。浏览器模块激活不会转发 Host Loader 配置。浏览器先验证公开数据，再创建控制器；显式 Client 选项覆盖页面默认值。重新加载页面读取更新后的设置。该数据不包含账号凭据或无关 Host 字段。

`requestTimeoutMs` 限制单次元数据请求的时长；`uploadTimeoutMs` 单独为较慢的二进制上传分片留出时间。`foregroundPollMs`、`backgroundPollMs` 和 `listPollMs` 控制刷新间隔。后台上传规则提供 MIME 类型、附件数量、图片和视频各自的大小上限，以及续传分片大小。用户通过现有账号页面登录，本包不建立另一套登录。

<a id="understand-the-implementation"></a>
## 理解实现

账号拥有的控制器向框架绑定的注入 hook 发布稳定 JSON 视图。组件持有查看控件与窄屏导航状态。账号或登录代次变化时立即清空旧视图，取消其请求和上传；响应必须与发起时的账号一致。卸载会取消并等待全部自有异步操作结束。

社区需求使用独立控制器、操作记录和鉴权代理 `/credits/api/community-demands`。公开列表、新发布和新接单要求后台明确声明审核能力与策略；旧后台保留「我的需求」和原参与人的授权会话。发布前必须明确同意公开，并展示标题、摘要、预算、可选预期交付日和公开附件。既有私密需求、消息和附件不会自动公开。公开列表仅接收已通过审核的公开字段。服务器确认唯一接单人后，该普通用户加入发布人的私密会话；管理员可以查看社区需求、参与人消息和媒体。关闭新需求后保留授权会话和原待确认操作的恢复。

论坛帖子、回复与点赞状态更新使用独立、按账号隔离的控制器和操作记录，并通过 `/credits/api/forum` 转发。图片上传遵循后台提供的类型、大小与数量限制，使用有界分块和原上传标识。只有服务器确认完成的图片才能绑定帖子或评论；携带这些附件时允许只发图片。提交冻结原 UUID、正文、有序附件标识和可选的同帖回复目标。后台支持时先查询原提交回执；旧后台保留用户明确重发原冻结文字请求的恢复方式。点赞结果不明时先读取当前状态。未知结果不会自动换标识或重发。网络失败保留已验证的内容；明确无权访问或不存在的详情响应会撤下缓存正文和媒体。

需求广场使用响应式封面卡片，展示公开标题、简述、原文预算、已填写的交付日与发布人。获得授权的公开图片或视频作为封面；没有媒体或加载失败时显示文字卡。点击卡片沿原标识打开详情。「我的需求」显示实际审核状态和仅发布人可见的驳回说明，并区分旧私密记录与社区记录。缺失的预算和日期不会补造。发布表单在公开说明后提供明确的媒体选择与拖入区域，可接受类型来自后台。上传完成后仅通过当前账号授权的内容地址显示预览；上传中仍保留进度与恢复控件。论坛使用每条占一行的横向列表，点击后从右侧滑出可关闭抽屉，桌面端保留左边列表。抽屉内并列展示正文与独立滚动的评论，回复框固定在评论区底部，抽屉较窄时改为上下排列。关闭抽屉恢复焦点，并保留未发送的回复文字。发帖和回复编辑框提供支持键盘操作的 Unicode 表情选择器，插入到当前选区，不触发提交。

“我的发布”和“我的评论”使用服务器按当前账号限定的游标分页。回复与点赞提醒使用真实接收人的未读数；侧边栏显示已验证的未读提示，打开提醒会定位对应帖子或评论，并明确确认原通知标识为已读。并发已读回执不会恢复较旧的未读数。论坛昵称使用独立、带版本校验的后台资料；保存响应丢失时，先 GET 核对再允许后续写入。作者名称不回退到账号手机号或登录名。缺少能力的旧后台继续使用原文字流程，不显示未接通的控件。

`showcaseItems` 独立于需求发布，提供公开案例元数据。每项包含分类、封面及明确选择的图片或视频地址，并可附来源与署名。标签页不扫描本地文件，也不生成客户记录；空目录保持为空。相对媒体地址沿用应用挂载前缀，允许 HTTPS 来源与本机回环开发地址，呈现层拒绝可执行地址及嵌入凭证。素材文件由部署的静态资源服务持有。

旧私密卡片保留原会话和草稿入口。核对未确认发布不会创建新需求。会话内使用紧凑列表、消息记录和输入框。Enter 发送可提交的消息，Shift+Enter 换行，确认输入法候选词不会发送。需求补充信息和上传规则可以展开查看。切换会话时，独立草稿保留在当前控制器生命周期内；应用重启后仅恢复已记录的待确认操作和上传。

紧凑列表以服务名称标识服务会话，原需求标题保留在摘要中。搜索包含服务名称、原标题、需求编号和服务端最近消息摘要；草稿正文仅在该草稿选中时可搜索。使用同一服务的不同需求仍以各自标识独立打开。草稿与服务端处理状态保持明确显示，已有服务头像不代表工程师在线。

后台声明支持服务档案时，目录使用有界服务端分页、搜索和分类筛选。更换筛选会取消旧目录请求，迟到的旧页不能替换新结果。服务档案描述需求方向，不代表独立在线员工。新需求先进入平台待分配队列，指派后仍保留最初的服务名称；旧后台继续使用直接选择工程师的目录与提交路径。客户档案仅在后台管理，不进入公开目录。

请求经本机鉴权代理 `/credits/api/demands` 转发，凭证及续期仍由 [credits-index](../../host/credits-index/README.zh.md) 负责。令牌保留在 Host。媒体元素使用本机附件标识和账号守卫，Host 重新授权内容访问，并透传 Range 响应以支持视频拖动播放。

每次新需求、消息、上传和验收在发送前保存账号隔离的持久操作标识及冻结请求正文。响应丢失时保留原操作进行准确重试，不更换标识重复提交；不同草稿彼此独立。消息发送成功和已读状态来自服务端回执。图片、视频按有界 `File.slice` 分片上传，分片结果不明时先查询偏移。重新选择文件后，先校验元数据与已记录分片的摘要再继续。文件内容不放入 JSON 视图或本地操作记录。

直接工程师流程的操作保留原存储空间和序列化正文。服务档案流程使用独立存储空间，新版读取器合并两者；返回旧客户端时，旧解析器不会读到仅适用于服务档案的记录。

社区发布、接单和消息分别保留持久操作标识。结果不明时提供原操作核对，已知失败保留实际错误分类；一单操作受阻不影响另一单。公开附件与会话附件保持不可变的可见范围，以有界增量方式校验整个文件的 SHA-256，并根据已验证的服务器偏移续传。社区消息保留服务器序号，本地未确认消息使用独立记录。已读确认仅针对当前选中且可见的会话与已确认消息序号。

<a id="model-experience"></a>
## 模型体验

<a id="human-engineer-requests"></a>
### 真人工程师需求

<a id="what-the-model-sees"></a>
#### 模型看到什么

`demands` 面板不添加提示词、工具、模型消息或 AI Session。需求会话与论坛讨论分别使用各自的后端服务。

<a id="token-effect"></a>
#### Token 影响

真人消息、论坛讨论及附件操作不发送模型请求，也不进入 AI 生成计费链路。

<a id="kv-cache-effect"></a>
#### KV Cache 影响

需求与论坛的导航和内容不改变模型上下文或提供商缓存。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与后续工作

- 工程师、上架、分派和私有附件存储依赖对应后台业务。
- 应用重启后，未完成的上传需要用户重新选择原文件。
- 本地操作记录要求浏览器存储可用；存储不可用或内容无效时，在发送前阻止新写操作。
- 报价、支付、合同和退款不属于本包。
