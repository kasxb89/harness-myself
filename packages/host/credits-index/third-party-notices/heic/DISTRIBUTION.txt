Yunshu HEIC decoder distribution and replacement information

This application uses unmodified heic-decode 2.1.0 (ISC) and libheif-js 1.23.5 (LGPL-3.0). libheif-js contains libheif and libde265 under the GNU Lesser General Public License. Their original notices and complete LGPL and GPL texts accompany this file. Their terms are not reclassified as permissive, and no commercial-license or owner-authorization exception is claimed.

The application calls the two npm modules through their existing Node interfaces; it does not inline either library into its JavaScript bundles or browser code. Library modification and reverse engineering for debugging such modifications are permitted. Compatible modified libraries may be substituted in your own application copy. The source archives under sources/ and sources.json accompany the library as its Corresponding Source under GPL section 6 and the LGPL additional permissions; the application JavaScript remains available as the application code used with the library.

Sources and rebuilding

sources.json records the exact upstream revisions, archive URLs and SHA256 values. Each archive is a complete unmodified source copy. The libheif-emscripten archive records the build workflow and libheif submodule pin; the pinned libheif source is included separately rather than left as an empty submodule directory. The default build enables libde265 1.0.15 only; AOM, OpenJPEG, WebCodecs and uncompressed codecs are disabled. No x265 encoder is part of this decoder build. Emscripten 3.1.61 and general-purpose build tools are prerequisites rather than application-specific source components.

Extract the libheif-emscripten archive. Extract the libheif archive into its libheif subdirectory, removing the archive's single enclosing directory. Follow .github/workflows/emscripten.yml for the JS or WASM target, including its USE_UNSAFE_EVAL=0 and USE_TYPESCRIPT=1 substitutions. Place the supplied libde265-1.0.15.tar.gz in the libheif build directory so build-emscripten.sh uses the accompanying source. The libheif scripts/install-ci-linux.sh and scripts/run-ci.sh document tool setup and compilation. Run dist-prep.sh and create the upstream libheif.tar.gz containing libheif/ and libheif-wasm/ as the workflow describes. In the extracted libheif-js source, install its declared development tools and run node scripts/install.js /path/to/libheif.tar.gz. This recreates the module layout used by heic-decode; compiler and build-tool differences can change generated bytes. No Yunshu-specific library modifications are applied. Yunshu pins only the dependency edge heic-decode@2.1.0>libheif-js to 1.23.5; the isolated Desktop installation copies this exact override and verifies the resolved edge, keeping future registry releases from changing the accompanying-source version.

Replacing a library in your own application copy

1. Quit Yunshu and back up the complete application. Work only on your own installed copy, never an update feed or downloaded package shared with other users.
2. The npm modules can be inside Electron's resources/app.asar. Use the standard @electron/asar tool to extract that archive, preserving the companion app.asar.unpacked files and its original unpack layout. Work on the extracted dsh/node_modules/heic-decode and dsh/node_modules/libheif-js module directories. On Windows these directories may already be unpacked. Preserve the public Node interfaces and provide every required JS/WASM resource.
3. The application records runtime file sizes and SHA256 hashes in dsh/desktop-runtime.json. After replacing a module, run the accompanying relink-runtime.mjs with Node 24 and the extracted dsh directory as its sole argument. This offline tool refreshes only changes within the two library directories and rejects modifications to any other runtime file. It never runs at application startup and never contacts a server.
4. Repack app.asar with the original unpack layout, including the refreshed runtime descriptor and modified libraries, and retain its unpacked companion. On macOS, if the operating system requires a new local code signature after modification, ad-hoc sign your own copy (codesign --force --deep --sign - /path/to/Yunshu.app). This does not require Yunshu's production signing keys. Reopen your modified copy; model APIs and update authorities do not change.
