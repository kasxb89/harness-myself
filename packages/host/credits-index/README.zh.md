# 额度 Host

[English](README.md) | 中文

## 概述

使用当前登录的产品账号查询余额、充值、分析用量并生成媒体。提示词帮写准备可编辑的图片或视频描述，不提交媒体生成。工作区视频项目规划模型支持的片段，依序生成，再发布经本地验证的成片。付费请求使用当前账号；取消不能保证已被上游接受的任务停止计费。

## 使用本包

额度 Host 通过校验本机来源的 `/credits` 路由转发账号、余额、充值和媒体操作。部署 API 根地址为 `https://8.133.202.230/harness`，模型请求使用其 `/v1` 后缀。所有上游请求均保留完整前缀，拒绝此 IP 根路径的 `/api` 和 `/v1`，不跟随重定向，并启用正常 HTTPS 证书校验。

### 账号会话

手机验证码与登录使用配置根地址下的 `/api/user/phone/challenge` 和 `/api/user/phone/login`。登录返回短期管理凭据 `access_token`、轮换的 refresh cookie 和账号专属 `relay_key`，模型请求仅使用该 relay key。Host 私密保存这些凭据，将会话绑定至后端根地址，并在管理凭据临近过期时等待同一次共享续期完成。续期和退出声明后端 Origin。Host 通过实时 `harnessAccount` 为产品模型路由授权；已存凭据或环境变量引用不能替代有效会话。退出会立即移除这项授权；并发的旧续期不能恢复它。将已存会话切换到另一后端时，需要重新手机登录。

桌面端通过已鉴权的 `POST /credits/api/activity`，向同一后端根地址下的 `/api/client-activity/heartbeat` 转发不含内容的活动状态。报告仅由当前手机号账号授权。随机 UUID 隔离每个原生进程与登录代次；退出停止该代次，匿名报告直接丢弃。Host 仅接受事件、前台状态、系统及应用版本，不接受调用方指定的用户 ID。失败直接丢弃，不影响模型请求、余额或登录；接收时间与在线过期由服务端确定。活动读取不发起凭据续期；应用常驻托盘期间，现有每 60 秒运行的 Host 模型目录计时器负责续期手机号会话。access 凭据过期时跳过样本，等待正常续期完成。

### 聊天模型刷新

每次列出产品路由模型前，先等待当前账号的 `harnessAccount.refreshModels` 结果。Host 使用该账号的 relay key 读取 `/v1/models`，排除已声明的媒体生成模型，并在适配器读取配置前同步非空聊天结果。并发读取共享同一次操作。成功返回空列表时不展示任何聊天模型，即使旧 profile 仍保留配置；读取不可用时返回目录失败，不把旧模型显示为当前可用。其他提供方路由保留原有的列表行为。

模型 `input` 缺失或为空时，仅在安装目录中精确相同的模型 ID 具有一致的非空输入声明时继承能力。发现操作只读取同一设置命名空间内的安装提供方目录，不联系其端点。明确的非空输入声明和其他模型设置在刷新及账号模型列表变化时保留。未知或能力冲突的 ID 不推断图像能力；继承的图像声明描述目录信息，不表示已验证中转请求。

启动和每 60 秒的定时器复用同一刷新操作。登录变化和退出会取消旧发现；提交前检查登录代次、已存会话身份、后端和有效期。卸载会取消并等待未结束的发现操作。界面可以请求新目录，无需等待定时器。公开定价仍用于描述媒体参数，账号模型端点决定其聊天列表；已声明或已选择的模型仍可能被上游的权限或计费校验拒绝。

### 充值

`POST /credits/api/recharge/wechat` 接受以元为单位的整数 `amount`，使用当前账号的 access token 创建一笔 Native 订单。响应提供 `outTradeNo`、`amount`、换算后的 `points`、`expiresAt` 和 `qrCodeDataUrl`；原始 quota 不是积分。提交订单前必须取得当前状态参数进行换算。下单结果未知时会明确报告，不自动再创建一笔订单。

`GET /credits/api/recharge/wechat/order?outTradeNo=...` 查询同一账号的订单。Host 原样转发后端状态，不设置别名，并附加换算后的积分。客户端将未知状态报告为待人工核对，不宣称支付成功。支付回调直接进入部署 API，由其负责给账号入账；产品仅在确认支付后刷新实时余额。

### 使用量分析

`GET /credits/api/usage?start=<seconds>&end=<seconds>` 返回当前登录账号按小时和模型汇总的用量。两个参数均为包含端点的正整数 Unix 秒，完整区间最多为 31 天。客户端先选择显示时区，再将自然日换算成秒。重复参数、账号选择参数和其他查询参数均被拒绝。

成功响应使用额度封装 `{ ok: true, payload: ... }`。payload 包含 `rows`、`start`、`end`、`asOf`（读取时刻的 ISO 时间）和 `delayMinutes: 0`。每行包含 `timestamp`、`model`、`billingRecords`、`consumedPoints` 及 `totalTokens`。Host 按小时和模型归并消费账单记录；零延迟字段表示不再等待旧聚合导出，不保证新扣费立即出现。消费记录数不等于请求数，单独记录的退款不从此处扣减。

Host 先使用 `/api/user/self` 核对产品会话中的账号，再通过 `/api/log/self?type=2&p=1&page_size=100` 读取选定区间的全部分页。它校验分页、账号身份、quota、token 字段及 JSON 字符串 `other`。失败、不完整或不一致的读取不会产生部分结果。管理员 token、账号搜索及部署凭据均不能替代当前登录账号。

实时 `/api/status` 读取提供 `quota_per_unit` 和 `usd_exchange_rate`。积分按 `quota / quota_per_unit × usd_exchange_rate × 1000` 计算，两个后端参数均没有写死的回退值。换算设置缺失或无效、源数据不可用或无效时，返回 `{ ok: false, code, message }`，不以零值替代。客户端负责可见错误提示和重试，读取不可用时保留之前的显示。

使用量读取共用本机来源校验、`timeoutMs` 和包含完整部署前缀的 `newApiBaseUrl`，仅使用当前账号的 access token。服务不可用时，产品不读取缓存 quota 或其他账号的余额。

聊天模型积分读取使用每个已提交 assistant 尝试的精确网关凭据，以及当前账号的 `/api/log/self?type=2&request_id=...` 记录。它核对 `/api/user/self`、凭据端点、账号和请求身份，再用实时状态参数换算已结算 quota。历史凭据缺失或来自其他网关时显示不可用；账单记录缺失时保持待结算，不捏造零值或部分合计。该金额只涵盖所选会话自身的模型尝试，不含图片／视频工具、独立提示词帮写及单独的子会话。读取不会提交模型请求，也不会根据 token 或账号余额差额推测消费。

经过身份验证的 `GET /credits/api/chat-usage` 接受一个 `session_id`、可选的正整数 `turn` 及可选的当前 `account_id`，拒绝重复、未知或携带权限的参数。Host 仅从自己的存储读取已附着 Session 的 `chatReceipts` 投影。该 Host 专用折叠从已提交事件恢复请求回执和轮次状态，不保留消息内容，也不增加 Session 事件。尚未结束的轮次为待结算；Session 查询服务、附着对象或投影缺失时为不可用。成功 payload 包含 `scope: 'chat-model'`、`status`、`accountId`、`settledRequests` 和 `totalRequests`，仅 `settled` 包含有限非负的 `points`。登录身份变化时，在响应前丢弃在途结果；显式指定旧 `account_id` 也会被拒绝。

相同选择共用当前登录拥有的在途操作；已结算结果、已核对的账号／状态上下文和精确请求 quota 共用 `chatUsageCacheTtlMs`（默认 5,000 ms，范围 1–60,000）。超过该间隔后重新向服务端读取换算参数。待结算和不可用结果不保留。所有选择的账单请求共用 `chatUsageConcurrency`（默认 4，范围 1–8）。浏览器断开不会中止其他消费方的在途操作。登录变化和退出会立即清空缓存并中止旧操作；插件释放会在 `timeoutMs` 内等待中止操作结束。每个上游 JSON 响应限制为 1 MiB。

### 提示词帮写

`POST /credits/api/prompt/assist` 仅接受 `{ accountId: string, sessionId: string | null, expectedSelection: { provider: string, model: string, reasoningEffort?: string } | null, kind: 'image' | 'video', prompt: string, instruction: string, references: string[], generation: Record<string, string> }`。Host 将 `accountId` 与有效产品会话比较，不匹配时在查询任何模型前返回 `ACCOUNT_CHANGED`；账号及模型选择标识不进入提示词正文。当前原稿、修改意见、生成参数，以及按上传顺序排列、带原文件名的 `@图片1` 素材标签构成模型输入；同一标签紧邻对应图片字节，并保留在私有请求记录中。PNG、JPEG 和 WebP 参考图必须是现有本机 `ma_` 资产；任意 URL、视频，以及客户端选择的路由或凭据均被拒绝。图片以内联聊天图像内容发送。标有其他账号的上传在调用前被拒绝；没有账号标记的旧上传保留原有本机行为。成功的额度响应封装在 `payload` 内包含 `{ prompt, model }`；失败包含稳定的 `code`，绝不返回上游响应正文或异常。只有原稿、账号、聊天及模型选择仍匹配时，客户端才将候选写入可编辑的创作提示词；请求失败时保留原稿。帮写不会提交媒体生成。

帮写使用当前聊天持久化的模型选择，没有明确选择时使用当前聊天默认模型。Host 通过同一聊天目录解析选择，要求配置的产品提供方及精确模型，并按该模型声明的图片输入能力校验参考图。浏览器 `expectedSelection` 用于发现过期请求，不能授权路由。服务缺失或模型不可用时明确报错；不支持图片的选择返回 `PROMPT_ASSIST_VISION_REQUIRED`，不自动换用其他模型。已知视频模型返回 `PROMPT_ASSIST_CHAT_REQUIRED`，要求用户选择聊天模型。旧配置 `promptAssistantModel` 和 `promptAssistantVisionModel` 仍可接受，但不决定模型。每次生成前，Host 还使用当前账号的中转 key 查询 `/v1/models`、排除声明的媒体生成模型和被网关误标端点的已知视频模型，并在发送前及接收候选前复核本地聊天模型和登录身份。随后使用同一 key 调用 `/v1/chat/completions`。使用 `deepseek-flash`、`deepseek-v4-flash` 或 `deepseek-v4-pro` 直接写稿时，通过文档规定的 `thinking.type` 开关明确关闭内部思考；聊天模型及其持久化选择保持不变，但聊天推理强度不作用于这项独立写稿任务。其他模型不携带 DeepSeek 专用字段。会话过期、未登录或缺少中转凭据时停止请求，部署 key 绝不作为回退。后台续期 token 时，只有上游确认相同账号 ID，才保留中转凭据。

请求 JSON 上限为 32 KiB；原稿最多 7,000 字符；修改意见最多 2,000 字符；参数摘要最多 16 个字符串条目，键最多 64 字符、值最多 256 字符。必须至少提供原稿、修改意见或参考图。最多九张不同参考图，合计不超过 12 MiB，单张不超过 6 MiB；MIME 与图片签名必须匹配。生成响应正文及账号目录上限为 64 KiB，最终提示词上限为 7,000 字符，`promptAssistantMaxTokens` 控制生成 token 上限，默认 8,192，接受 512 至 16,384 的整数。`promptAssistantTimeoutMs` 为整个操作提供独立于其他 API 的统一截止时间，默认为 60,000 毫秒，接受 1 到 120,000 毫秒的整数；断开连接或插件 dispose（资源释放）会取消上游工作，dispose 等待请求结束。不自动重试上游请求。发出聊天生成后，超时、传输故障、取消或上游报错均返回 `PROMPT_ASSIST_RESULT_UNKNOWN`，表示结果未知且可能已经计费。无效的生成数据同样提示可能计费；用户应先查看用量，再决定是否重试。模型目录阶段失败时尚未发出聊天生成。

调用模型前，Host 将账号 ID、聊天、所选提供方/模型/推理强度、实际采用的思考开关、token 上限、准确的系统和用户文本，以及参考图元数据保存到 `stateDir/prompt-assists/<random-request-id>/request.json`。`prompt-assists/references` 下按内容寻址的图片文件，为每个 SHA-256 摘要保留一次不可变字节；普通上传可能覆盖资产 ID，因此不足以重建请求。目录权限为 `0700`，文件为 `0600` 且以独占方式创建。`outcome.json` 保存经过校验的候选或安全失败码、是否已发出聊天生成，以及可用时的私密 HTTP 状态、后台请求 ID 和有界结构化错误字段。可解码的生成响应还记录识别到的结束原因、最终文本与思考的字符数，不保留思考原文。当前中转 key 和凭据模式会被移除，不保留自由文本上游正文；浏览器响应不含这些诊断。请求 ID 可关联后台报错页中的转发失败。输入记录失败会阻止发送；结果记录失败返回 `PROMPT_ASSIST_RESULT_STORAGE_FAILED`，表示可能已经计费但候选不可用。崩溃可能留下没有结果的请求；记录保留到部署者主动删除，不自动清理。这个独立媒体流程不添加 Session 格式或 agent loop（智能体循环）行为。

### 创作内容发布

`GET /credits/api/creation/content` 将部署后台的公开文档转发为 `{ ok: true, payload }`。`GET` 与 `HEAD /credits/api/creation/assets/:id` 转发不可变的 `cc_` 内容哈希图片和视频，支持单个字节范围读取。这些读取校验来源，使用 `newApiBaseUrl` 与 `timeoutMs`，不发送账号或部署凭据，拒绝上游重定向及不符合预期的 MIME 类型，文档上限为 5 MiB，媒体上限为 100 MiB。连接断开或插件卸载会停止传输，卸载等待操作结束。错误仅公开 `CREATION_CONTENT_UNAVAILABLE`，绝不返回上游正文。[创作内容读取器](../../client/creation-content/README.zh.md) 负责文档校验、刷新及使用方状态。

### 聊天创作计划

技能注册服务可用时，内置 `yunshu-video-director` 技能使用 [cinematic-director](https://github.com/wuwangzhang1216/DirectorSKILL) 与 [video-storyboard-gen](https://github.com/anyhui/video-storyboard-gen-skill) 的精简摘录和适配内容，指导剧情、走位、连续性、参考素材重构、分镜、对白及字幕。[固定来源及适配说明](third-party-notices/sources.json) 和两份完整 MIT 许可随包分发。生成时不运行社区脚本，也不加载整套参考库。简单且提示词完整的短片直接调用 `generate_video`；工作区参考素材可使用 `generate_video_project`，即使只生成单段。明确的剧情或连续人物创作使用显式计划，长视频仍使用该原生项目工具。原生工具负责校验、提交、轮询、下载、剪辑、发布和恢复。画面切换不必各自生成一段计费视频。不强制额外生成参考图、多个备选稿或单独请求规划模型；工作流程不能控制上游渲染耗时。

剧情、广告和多参考图视频稿采用六部分中文结构：剧情概述；每份真实素材的职责及采用、排除内容；稳定的人物关系与场景风格；包含动作、运镜、对白时间窗、音效和配乐的连续分镜时间轴；连续性要求；禁止项。分镜沿用用户提供的图片编号。明确要求如“不要字幕”优先；台词无法在指定时长内自然说完时，必须指出冲突，不能静默加速。简单请求仍保持简短。这份共享指导不增加规划生成请求，也不要求模型编写拼接代码。

共享编导指导要求聊天和视频 AI 帮写将平台或上游故障概括为安全中文，不复述 HTTP 响应、诊断 JSON、代码、堆栈、内部路径或凭据。原生图片和单段视频的工具描述也附带同一份简短规则，覆盖未加载编导技能的聊天调用。已确认的登录、产品积分、文件校验及取消失败保留可操作的恢复说明。付费结果未知时，先检查已有任务与产物再决定是否重试。原生图片与单段视频的失败回执在既有状态和诊断消息之外保留可用的稳定 `code`，产品界面据此区分未知结果，不解析上游文字猜测。这些指导保留真实工具结果和必要协议字段，也不限制用户明确要求的软件或代码诊断。

独立的 `yunshu-minimax-h3` 技能依据[官方提示词指南](https://github.com/MiniMax-AI/MiniMax-H3/tree/main/skills/h3-prompt-writing) 提供本地编写的 H3 格式指导，不重新分发官方技能原文件。聊天仅在为 MiniMax-H3 编写提示词且确有需要时加载它。视频 AI 帮写仅当 `generation.model` 精确等于 `MiniMax-H3` 时加入同一份格式指导，与所选聊天模型无关。指导分别描述带标签的对白原文、环境声和背景音乐，保留对白与画面文字的原语言。用户可见的创作要求、人物设定、素材说明、分镜、场景、运镜、动作和提示词默认使用简体中文，除非用户明确要求其他输出语言；英文草稿不改变这个默认值。协议字段、标签和资源标识保留原拼写。其他视频模型只接收共享编导指导，图片帮写接收同一语言规则，不接收任何视频指导。选择过程不下载在线指南，不请求翻译，也不增加聊天生成请求。

`update_creation_plan` 保存完整的图片或视频创作描述、稳定人物设定、有明确标识的参考素材，以及包含镜头、场景、动作、对白原文和字幕指示的有序分镜。修改时明确指定 `plan_id`，不能移除已有生成记录的镜头或图片素材。源路径只描述参考资料，不授权读取或预览任意文件；空来源表示尚未生成的素材。规划不请求上游。`generate_image` 和 `generate_video` 接受 `plan_id` 与 `shot_id`；`generate_video_project` 接受 `plan_id` 与有序 `shot_ids`，与实际支持的片段一一对应。`generate_image` 也可以用 `asset_id` 代替 `shot_id`，生成已有的图片素材，包括视频计划中的人物参考图。真实输出归属该素材及引用它的人物，不显示为完成的镜头或成片。关联缺失、不匹配、已在运行或提交结果未知时在计费前拒绝。未提供计划的调用创建自己的最小记录，因此聊天生成成功后仍能找到产物；调用不会隐式选择最近的项目。

图片重构和后续视频生成可以使用已上传的 `ma_` id，或同一明确计划内实际生成的图片产物 id、路径。Host 只读取该账号、聊天和工作区的准确记录，验证已保存图片，并将有界字节物化成本机上传引用，再执行常规提供方校验。因此产物目录位于工作区外时仍可复用，不新增文件系统读取根。`asset_id` 是计划标识，不是提供方引用 id；预览 URL 和任意文件路径不能作为图片参考。原有工作区视频参考仍执行通常的文件权限校验。

`generate_image` 可直接编辑当前聊天用户附件中的图片，使用准确的附件 id 或投影后的只读路径，无需先复制到工作区。附件服务验证已保存字节；其他聊天图片及任意附件路径不授予读取权限。可读工作区图片仍执行通常的路径包含和文件检查。Host 将这些有界图片物化为私有 `ma_` 引用，再通过当前账号的中转 key，在完整配置的 API 前缀下向 `/v1/images/edits` 发送带 `image[]` 的 multipart 编辑请求。所选图片模型必须声明编辑能力；仅支持文生图的模型不会被静默开启编辑。

`yunshu-internal-gpt-image-2` 使用聊天与 AI 创作共用的独立任务合约。Host 在上传任何字节前验证最多六张已授权的 PNG/JPEG/WebP 参考图，每张不超过 10 MiB。随后通过已鉴权的 `POST /v1/uploads/images`，用 multipart 的 `model` 和 `file` 逐张上传，再把经过验证、位于 `files.toapis.cn/uploads/` 或 `files.toapis.com/uploads/` 下的 HTTPS 回执 URL 作为 `reference_images` 提交给 `/toapis/v1/images/generations`。生成仅携带 `model`、`prompt`、`n: 1` 和可选的 `reference_images`；输出设置由服务端决定，不透传像素尺寸或其他 OpenAI 参数。回执要求 MIME 与大小匹配、id 非空，URL 不含凭据、查询或片段。两条路径都保留部署前缀，只使用当前账号的中转 key。文件无效、上传失败或回执无效时，提示原始文件名并在生成前停止。上传和生成均不自动重提；普通 OpenAI 编辑保留原 multipart 路由。

修改已保存项目之前，`get_creation_plan(plan_id)` 返回有界的完整规划字段，字段名称与 `update_creation_plan` 一致。读取同样校验账号、聊天及工作区归属，不包含执行请求或登录数据，不改变状态，也不请求上游。局部修改应先以这份权威记录保留其他人物、素材和镜头。

`stateDir/creative-projects/<project_id>/project.json` 下的私密版本化记录将计划和调用结果绑定到账号、聊天及工作区。付费提交前以仅所有者可读写的原子替换保存记录；每张图片落盘后立即登记，批量生成后续失败时仍保留前面的文件。账号或登录代次变化后拒绝晚到写入和抽帧结果。长视频任务、已保存片段、剪辑和最终完成状态仍以已有视频 manifest 为准；创作记录只关联它，不解析进度文案或复制状态。单次生成在可能计费前保存提交标记：重启后已发出但未结束的调用显示为结果未知，仅准备尚未发出的调用显示为中断。每个镜头使用最近一次明确调用的状态，旧产物继续保留；未知计费事实始终可见，并阻止对受影响镜头再次提交。显式恢复保留并发的计划修改与已保存素材。列出或打开项目均不启动或继续生成。

已通过 Host 认证的客户端读取 `GET /credits/api/creative/projects?session_id=...`，返回 `{ ok: true, payload: { accountId, projects } }`，使用不包含凭据的[浏览器类型](src/creative-types.ts)。结果同时按账号和精确聊天过滤。`GET` 与 `HEAD /credits/api/creative/media` 要求会话、项目、已登记产物 id，以及可选的抽帧索引；查询参数中的文件路径不能授权读取。媒体支持单个字节范围，拒绝缺失、符号链接文件，以及打开期间检测到的文件替换。媒体读取在开始响应前复核原账号和登录代次；读取期间退出或切换账号会拒绝尚未开始的响应。退出登录返回 `AUTH_REQUIRED`。损坏记录及存储不可用返回安全、可见的错误，不伪装成成功空列表。

每份投影包含仅根据计划计算的 `planRevision`、所属 `sessionId`、保留调用 `tasks` 及已完成和总镜头数。素材图片、生成片段和成片进入合并产物列表，按实际路径去重。计划 `durationSeconds` 可编辑，与最近提交时长 `actualDurationSeconds` 分开保存。`POST /credits/api/creative/plan` 接受 `{ session_id, project_id, expected_revision, change }`，执行有界的镜头修改、排序、人物与素材增改或明确删除，不提交生成。版本过期返回 HTTP 409 和 `CREATIVE_PLAN_STALE`；正在运行的关联成员与保留执行关联受保护。`GET`/`HEAD /credits/api/creative/reference` 通过 `session_id`、`project_id` 和 `asset_id` 仅读取该计划确切的上传图片素材，发送字节前复核账号。

当前 AI 图片和视频面板请求包含 `session_id` 和 `account_id`。Host 在提交前要求经过认证的连接、相同登录账号及准确的活动工作区聊天，再通过与聊天相同的存储保留独立最小项目和实际已保存产物，不猜测最近项目。两个关联字段均缺省的旧请求保留原媒体合约。插件卸载取消并等待所属面板生成结束；上游已受理的任务仍可能继续计费。

已保存的视频片段及成片通过当前会话的沙箱和内置 FFmpeg 抽取三张真实 JPEG 预览，保存在原工作区的 `.yunshu-creative/previews`。抽帧失败标记 `previewUnavailable`，保留真实视频及其生成结果。计划和记录最多为 2 MiB，每个项目最多包含 64 个人物、128 份素材或镜头、256 次调用；列表最多读取 1,000 个保留的项目目录，项目视图合计不超过 8 MiB。不自动清理记录。人物一致性、对白内容、口型及字幕时序在实际检查成片前仍属于未验证的创作要求。

### 视频能力与参考素材

视频提交和状态查询使用所选能力的 `route`；公开定价明确指定的路由优先。MiniMax-H3 使用 `POST /v1/video/generations` 和 `GET /v1/video/generations/:id`，其他视频模型保留原有协议。`data` 内的通用任务响应支持大写 `NOT_START`、`SUBMITTED`、`QUEUED`、`IN_PROGRESS`、`SUCCESS` 和 `FAILURE`。成片通过 `/v1/videos/:id/content` 读取，保留配置中的 `/harness` 前缀，并使用当前账号的中转 key。渠道的聊天测试不能验证视频生成。

视频菜单优先读取公开定价 `parameters`（字段映射或 JSON Schema 的 `properties`）中明确的 `seconds` 或 `duration` 声明，其次读取 `billing_usage_schema`。数值枚举或有限的 `minimum`/`maximum` 范围选出 1 至 3600 秒内的整数，并覆盖模型表；排他边界和 `multipleOf` 进一步缩小时长菜单。缺失、格式错误或无上限的声明保留已知模型限制；计费样例不授予时长或额外参考槽位。分辨率枚举和常量使用相同的实时优先级。当前 H3 响应只声明未限定范围的数值秒数字段，因此保留已知的 4–15 秒菜单。公开定价列出某个模型，不代表特定账号已可用它生成。

明确的 `oneOf` 将 `properties.resolution.const` 或 `.enum` 与有限的 `properties.seconds` 或 `.duration` 配对。得到的 `durationByResolution` 菜单同时约束面板请求和项目规划；未列出的分辨率不可用，并且必须选择分辨率。例如，生产方可以明确发布 480P/768P 为 4–30 秒、2K 为 4–15 秒的两个分支。这说明解析器支持的格式，不表示当前 API 或尚未明确的上游支持这些组合。Host 在模型提交前拒绝不支持的组合、小数或非数值时长。

本机 `POST /credits/api/assets` 按真实字节识别图片，不依赖后缀或 MIME 提示；完整解码 PNG/JPEG/JFIF/WebP/AVIF/GIF/BMP/TIFF/HEIC/HEIF，纠正方向后生成模型可用的 PNG 或 JPEG。原图上限为 32 MiB、4,000 万像素；转换后每张不超过 6 MiB，一次生成中的图片合计不超过 12 MiB。动态及多页图片明确取首帧。响应保留原文件名、实际来源格式、尺寸、转换后的 MIME/大小及转换信息；结构化失败标明对应上传，不泄露解码器异常。`GET`/`HEAD /credits/api/assets/preview?asset_id=...` 通过宿主认证及上传账号校验后提供转换后的图片，响应使用 `Cache-Control: no-store`。视频和音频仍要求 MIME 与文件签名匹配，分别限制为 32 MiB 和 15 MiB。生成请求的全部参考字节不超过 48 MiB，编码后的完整请求不超过 64 MiB。H3 全部参考素材放在同一个完整的 `metadata.content` 数组；首尾帧不能与通用参考槽位混用，自适应比例需要实际图片或视频输入。媒体校验不证明上游生成质量。

聊天工具的 `reference_audios` 接受已上传素材编号或可读的工作区 WAV/MP3 路径。视频项目保留这些引用用于恢复。可选的 `audio` 请求只有在所选模型声明了对应开关时才发送提供方开关。H3 固定原生音频：接受 `audio: true`，不添加上游不支持的请求字段；`audio: false` 则在提交前拒绝。

### 产物保存位置

组合提供可选的[产物保存服务](../../deliverables/artifacts-index/README.zh.md) 时，图片、下载媒体和单段视频在生成或保存前捕获当前目标目录。同一次操作的全部输出使用同一目标，即使期间用户更改了设置。新视频项目持久化已捕获的发布目录；剪辑仍在工作区沙箱内执行，随后由 Host 将成片复制到该目录，不替换已有文件。发布失败保留原片和暂存成片，供显式恢复，不重复已完成的付费提交。本地视频剪辑使用同一发布服务。

未提供该服务时，图片和单段视频继续使用 `stateDir/media`，视频项目继续使用工作区输出目录。没有发布目录字段的旧项目记录恢复时保留原有工作区行为。更改偏好不会移动已有文件或改写旧聊天路径。

### 本地视频剪辑

项目剪辑器使用桌面端提供的 `DSH_VIDEO_RUNTIME_ROOT` 目录，不搜索 PATH。付费生成前会验证两个可执行文件，并在选定输出目录实际执行一次 H.264/AAC 编码，拒绝只读或逃逸的输出目录。每个进程均经过当前会话的子进程服务和已解析的沙箱策略，不拼接 shell。输入必须是工作区内的普通文件，或项目所有者已授权的确切私有片段目录中的普通文件；私有片段路径拒绝符号链接。当前聊天附件位于工作区之外时，模型先通过现有文件工具把已获读取权限的附件复制进工作区。协议访问仅允许本地文件和管道。

剪辑保留原片，按明确的开始和结束时间裁剪，将画面等比缩放并补边到首段画布（或部署时明确指定的画布），并将尺寸取为偶数，转换为配置的帧率，并将音轨统一为双声道 48 kHz。没有音轨的片段补静音。最多 `videoEditSinglePassMaxInputs` 份输入（整数 1–32，默认 3）在同一滤镜图中完成解码画面的标准化和拼接，最终只编码一次固定帧率 H.264/AAC 成片。每份输入限制为单线程解码，并分别限制协议为本地文件和管道；更多输入保留原有的串行标准化与最终编码，限制同时运行的解码器数量。不添加转场、字幕或配乐。可选的成片时长会裁掉拼接结果的末尾，素材不足则明确拒绝。FFprobe 在成片以独占、同卷原子方式发布前核对时长；已有目标文件不会被替换。取消和超时会终止并等待受管进程范围退出，再清理临时文件。剪辑失败不会发布候选文件；已经完成的原片保留，可在后续剪辑中复用。这项修改缩短本地拼接时间，不缩短上游生成耗时，也不验证模型生成的人声、口型或字幕质量。

### 视频项目

工作区聊天可通过 `generate_video_project` 制作超过所选模型单段时长上限的完整视频。规划器先最小化计费片段数量，再最小化多余秒数：模型支持对应时长时，40 秒请求使用 `15 + 15 + 10`；仅支持固定 15 秒时生成三段，并裁剪为 40 秒。首次计费提交前，系统验证所有分镜请求和本地剪辑工具。可选分镜说明的数量必须与规划片段数相同；上传引用编号和可读工作区素材均经过当前会话校验。生成只使用当前登录账号的中转凭据，每次提交前核对捕获的账号与登录状态；退出、过期或切换登录会阻止后续新增计费。

明确提供 `shot_durations_seconds` 时，按这些受支持的分镜时长逐一执行，总和必须等于请求总时长。关联创作计划且每个所选镜头都有时长时，固定流程使用已保存时间轴；时长填写不完整时要求修正，不静默重新分段。没有明确分镜提示词时，流程按所选镜头组装已保存的场景、运镜、动作、对白原文、字幕和人物设定，仅添加该镜头关联的图片素材和人物参考，优先使用最近实际生成的素材图片。所有引用及时长在首次计费前校验，不额外请求规划或翻译模型，也不让 agent 编写拼接脚本。已保留项目仍恢复原先保存的完整请求。

每段请求均保留完整主说明作为共享上下文，并明确只生成当前分镜、对应时长和分配给它的台词。分镜说明补充当前镜头的要求，不替换主说明。合并后的提示词超过提供方上限时，在任何计费提交前失败，绝不截断用户原文。已有项目恢复时仍使用原先保存的完整请求。

用户要求对白时，指令区分稳定的说话人、台词原文与语言、画内发声、画外旁白、环境声和背景音乐。指令保留明确的静音要求，只在用户要求时请求字幕。H3 专属说明遵循其原生对白格式。这些均为生成要求：剪辑器不合成人声、不对齐口型，也不创建字幕轨；文件验证不证明成片确实出现了指定对白或同步效果。

项目使用已有的会话所属后台任务。工具返回规范的 `job_id`、`project_id` 和 `plan_seconds`；现有任务工具负责读取进度和取消。最终成功结果只包含经独立验证且实际保存的 `final_path` 和片段路径。代理通过现有 `present` 工具和可点击的产物链接交付最终文件。本地取消会停止后续提交和本地处理；中转服务没有取消操作，已被上游接受的任务可能继续运行和计费。

`stateDir/video-projects/<project_id>/manifest.json` 中的私有记录仅所有者可读写，保留账号编号、非秘密登录指纹、所属聊天与工作区、原始说明和完整已准备请求、分镜计划、上游任务编号、已保存片段路径及最终状态。每次提交前以及任务编号和片段保存后均原子替换记录；记录不含凭据或上游原始响应。原始片段保留在私有项目缓存，供剪辑和恢复使用。每个校验完成的片段及最终成片还通过产物保存服务发布到生成前捕获的保存目录；后续片段失败时，已完成片段仍可在产物库找到。旧版仅使用工作区的项目将片段发布到原工作区的 `videoProjectOutputDirectory`。经过授权的项目读取及 `video_project_status` 会在本机补发布已有历史片段，不再提交生成请求。可重试的本机复制失败时，已授权项目继续可见并提示发布失败；恢复保存目录或原文件后刷新即可重试复制。本地剪辑先在沙箱内将成片保留到工作区，再执行发布；返回的媒体路径指向已发布副本。记录和素材不自动清理。`video_project_status` 按账号、聊天和工作区校验读取权限。进程重启后保留的是记录，不会虚构仍在运行的任务；显式调用 `resume_video_project` 会复用已保存片段、读取已知任务编号，再决定是否提交从未提交的剩余片段。没有已持久化任务编号的提交属于未知结果，可能已计费，绝不自动重提；失败的上游任务同样需要明确创建新项目，或剪辑已保留片段。

可配置 `videoProjectMaxSeconds`（默认 300）、`videoProjectMaxSegments`（32）、`videoProjectPollIntervalMs`（6000）、`videoProjectTaskTimeoutMs`（900000）、`videoProjectDownloadMaxBytes`（536870912），`videoProjectReferenceMaxBytes`（每个本地引用 20971520），以及相对于工作区的 `videoProjectOutputDirectory`（`artifacts/videos`）。视频内容下载的完整传输期限至少为 300000 ms，模型目录、提交和状态请求仍使用 `timeoutMs`；原有任务取消与单段任务期限也继续约束下载。内容读取中断返回 `VIDEO_DOWNLOAD_UNAVAILABLE`，清除未完成文件，保留已知任务供显式恢复，不再次提交。生成前，完整记录连同任务与路径元数据的预留空间必须不超过 64 MiB。这些限制在计费前生效。镜头连贯性仍取决于提供方；管线提供有序分镜说明与共享参考素材，不会承诺模型尚未生成的主体一致性或转场画面。

图片生成、单段视频提交、长视频项目和 AI 帮写仅在实际 HTTP 403 响应含网关精确错误码 `insufficient_user_quota` 时返回 `INSUFFICIENT_BALANCE`；OpenAI 错误封装还须具有网关的 `new_api_error` 或图片协议的 `invalid_request_error` 类型。上游额度不足、渠道欠费、令牌额度、普通 403 和传输故障均不表示用户余额不足。明确资金拒绝会停止固定视频流程并保留已保存片段。网关也可能在上游受理后因追加费用而返回此错误，因此未确认的提交继续保持未知状态，即使充值也不能自动重发。原生任务插件若已把错误码改为 `permission_denied`，产品无法恢复原始原因，因此仍显示通用错误。不另发余额估算或付费探测请求。

<a id="model-experience"></a>
## 模型体验

### 使用量分析

#### 模型接收的内容

通过 `/credits/api/usage` 进行的使用量分析仅供浏览器读取，不贡献模型输入。

#### token 影响

使用量读取不请求模型，也不消耗模型 token。

#### KV Cache 影响

使用量分析不改变模型上下文或 KV 缓存。

### 提示词帮写

#### 模型接收的内容

提示词帮写使用所选聊天模型发起一次不流式返回的生成。视频帮写与内置聊天技能共用编导指导，包括可拍摄的剧情节奏、人物一致性、镜头、对白原文、口型及按需字幕时序；这些是生成要求，不是已验证的成片结论。系统指令及用户文本将原稿、修改意见、参数和图片视为不可信参考资料。模型返回纯文本候选提示词。每次修改都发送当前编辑后的候选及新意见，而不是隐式对话历史。模型可见输入及经过校验的结果，可通过上述私有独立记录重建。

#### token 影响

每次帮写或修改请求均按当前账号计费，生成输出上限为 2,048 tokens。原稿文字、修改意见、参数及参考图片均贡献输入用量。精简共享视频指导会贡献输入 token；H3 格式只在选择该生成模型时加入，不增加帮写请求。

#### KV Cache 影响

每次明确发起的请求都提供当前原稿和修改意见，不包含隐式对话历史。这个独立流程不管理提供方缓存。

### 视频项目与剪辑

#### 模型接收的内容

可选的内置编导技能通过现有的、有日志的技能机制贡献目录描述，并在加载时提供编导及原生工作流程指令。视频工具（包括 `generate_video_project`）向模型上下文加入分镜规划、本地剪辑、持久状态和显式恢复说明。工具说明要求代理包含台词原文、语言、说话人及字幕要求。每段提供方提示词保留主说明，限定当前镜头，并加入按需生效的音画指令。代理必须检查实际成片，才能声称人声、口型或字幕已经出现并同步。分镜说明来自已记录的工具输入和保存的有序说明。现有任务工具通过常规日志结果呈现进度和最终路径。视频项目记录保留完整生成请求，无需改变会话格式或代理循环。创作规划工具通过常规工具历史记录结构化输入与返回的计划 id。生成调用记录明确的计划和镜头关联。浏览器项目读取与可选抽帧不加入模型输入，不请求上游，也不消耗模型 token；后续修改仍通过明确的、有日志的工具调用完成。

#### token 影响

工具声明、已加载的技能文本与已记录结果贡献常规代理上下文 token。原生工作流程不会额外调用聊天生成；计费的视频模型调用遵循已持久化的片段计划。

#### KV Cache 影响

工具声明与已记录结果遵循常规 Session 请求处理。视频生成和本地剪辑不添加隐式聊天历史，也不管理提供方缓存。

## 已知限制与延后工作

<a id="known-limitations-and-deferred-work"></a>

- 数据源按小时分组，通常每五分钟写入一次。这些汇总无法提供准确请求时刻、扣除退款的净支出、输入输出 token 拆分或实时余额账本。用量响应最多包含 100,000 条源记录；超限时明确报错。
- 视频完成只验证文件已保存及其时长，不验证台词内容、口型同步或字幕准确性。本地剪辑保留每段的第一条音轨，不混合独立的人声与配乐轨，也不保留软字幕轨。
