# 额度 Host

[English](README.md) | 中文

## 概述

使用当前登录的产品账号查询余额、充值、分析用量并生成媒体。提示词帮写准备可编辑的图片或视频描述，不提交媒体生成。工作区视频项目规划模型支持的片段，依序生成，再发布经本地验证的成片。付费请求使用当前账号；取消不能保证已被上游接受的任务停止计费。

## 使用本包

额度 Host 通过校验本机来源的 `/credits` 路由转发账号、余额、充值和媒体操作。部署 API 根地址为 `https://8.133.202.230/harness`，模型请求使用其 `/v1` 后缀。所有上游请求均保留完整前缀，拒绝此 IP 根路径的 `/api` 和 `/v1`，不跟随重定向，并启用正常 HTTPS 证书校验。

### 账号会话

手机验证码与登录使用配置根地址下的 `/api/user/phone/challenge` 和 `/api/user/phone/login`。登录返回短期管理凭据 `access_token`、轮换的 refresh cookie 和账号专属 `relay_key`，模型请求仅使用该 relay key。Host 私密保存这些凭据，将会话绑定至后端根地址，并在管理凭据临近过期时等待同一次共享续期完成。续期和退出声明后端 Origin。Host 通过实时 `harnessAccount` 为产品模型路由授权；已存凭据或环境变量引用不能替代有效会话。退出会立即移除这项授权；并发的旧续期不能恢复它。将已存会话切换到另一后端时，需要重新手机登录。

共享同一会话文件的 Host 通过文件锁协调续期与会话修改。持久化续期状态在协作 Host 间共享冷却和访问凭据拒绝记录；旧版客户端不参与这些锁。明确收到 HTTP 401 的 access token 即使尚未到期也不再复用。续期收到终态 HTTP 401 时，只清除原先捕获的账号与凭据代次。晚到的成功或拒绝响应不能覆盖新登录或清除其凭据。dispose（资源释放）取消恢复计时器和 HTTP 工作，再等待续期与拒绝状态写入结束。释放后完成的读盘或 HTTP 响应不能发起续期或清除登录。后台故障报告若抛错，则通过独立警告报告恢复失败，不包含凭据。

`GET /credits/api/session` 保留现有的 `ok`、`code`、`signedIn` 和 `liveness` 字段。已存登录暂时无法确认访问权限时，仍返回 `ACCOUNT_UNAVAILABLE`、`signedIn: true`、`liveness: 'unknown'`；这是可恢复的账号读取结果，不代表访问已验证，也不是文档非法。可选字段 `failure: { reason, stage, status? }` 同时出现在顶层和 `payload`。reason 区分 `network`、`timeout`、`rate_limited`、`upstream_unavailable`、`upstream_rejected`、`protocol`、`identity_mismatch`、`renewal_unavailable` 和 `storage`；stage 为 `account-read` 或 `renewal`，仅实际收到 HTTP 响应时包含 status。续期诊断仅保存在内存，并绑定精确的凭据代次；未在本 Host 观测的共享冷却使用 `renewal_unavailable`。这些字段不包含凭据、远端正文或异常文字。临时错误保留登录及有界续期策略；已确认的续期终态 401 会立即返回未登录，即使它发生在实时账号读取过程中。本地锁或写入失败阻止无效登录清理时，返回可恢复的存储错误；清理成功前持续阻止受保护请求。

续期按 HTTP 429 与 `Retry-After` 判断限流，不要求 JSON 正文，兼容旧版空响应。有效的秒数或 HTTP 日期均按要求等待；临时 HTTP 500/503 及传输故障保留登录，并使用有界指数退避。Cookie 轮换未确认时，只在 API 的 30 秒恢复窗口及配置重试次数内重试旧 cookie。任一限制耗尽后仍保留已存登录，但恢复需要新确认的 cookie 或重新登录，不再重放旧 cookie。这项恢复绝不重试图片、视频或 AI 帮写的生成 POST。

`refreshRetryBaseDelayMs` 默认为 1000，`refreshRetryMaxDelayMs` 默认为 60000；两者接受 1 至 2,147,483,647 的整数毫秒，最大值不得小于基础值。有效的服务端 `Retry-After` 可以超过本地退避上限，客户端不缩短它。`refreshRecoveryRetryLimit` 默认为 2，接受 0 至 5 的整数，限制轮换未确认后的额外兑换次数。服务端 30 秒恢复窗口不是可配置的客户端超时。

手机号请求透传 `idempotency_key`，兑换还透传不透明的 `challenge_id`。发出请求前，Host 将独立的短信和兑换请求标识原子保存到私有文件，并绑定完整后端根路径和手机号。恢复记录保留参数指纹、验证请求标识、服务端有效期和冷却时间，不包含验证码或会话凭据。验证码过期后清理验证请求记录，但结果未确认的兑换继续保留原提交时间、请求标识和手机号绑定，直至完成确认；成功回执的回放期限由 API 判断。未登录时，`/credits/api/session` 返回非秘密的待处理恢复字段；`/credits/api/session/phone-recovery` 只读同一状态，不发出短信请求。发送结果不明或仍在处理时只能查询原短信请求。只有 `delivery_status: not_sent` 能确认未发送，允许用户明确重新请求时使用新请求标识。不可用响应缺少该回执时，保留原请求标识并提示发送结果未确认。稳定错误码选择安全提示，上游原始错误不向用户显示。只有账户、访问令牌有效期、中转凭据和同源刷新 cookie 均有效的登录结果才会提交。失败、不完整和待安全验证的结果保留既有会话，迟到结果不能撤销退出操作。Host 按 `method` 与 `available` 读取 API 方法项；只有明确可用的 `2fa` 流程通过同源安全验证端点完成，流程凭据仅留在 Host。此既有端点没有新增重放保证：结果不明时停止该流程并要求重新短信认证。

桌面端通过已鉴权的 `POST /credits/api/activity`，向同一后端根地址下的 `/api/client-activity/heartbeat` 转发不含内容的活动状态。报告仅由当前手机号账号授权。随机 UUID 隔离每个原生进程与登录代次；退出停止该代次，匿名报告直接丢弃。Host 仅接受事件、前台状态、系统及应用版本，不接受调用方指定的用户 ID。失败直接丢弃，不影响模型请求、余额或登录；接收时间与在线过期由服务端确定。活动读取不发起凭据续期；应用常驻托盘期间，现有每 60 秒运行的 Host 模型目录计时器负责续期手机号会话。access 凭据过期时跳过样本，等待正常续期完成。

创作工具仅向配置 API 根地址下的 `/api/client-errors` 上报已声明的本地错误码、阶段及已知的准确模型 ID。报告使用原账号当前的 access token，不包含提示词、路径、原始错误或调用方自报身份。报告仅读取已提交的登录缓存，最多两路同时发送、每条只尝试一次、三秒截止，不延迟或重试生成。未登录、账号已变化或发送容量已满时丢弃报告；旧服务器及拒收不改变原工具结果。后台视频项目失败使用同一个有界报告器。接收时间、用户身份及独立客户端错误页由后端负责。客户端报告描述已观察到的流程结果，不代表平台故障次数。待确认或结果未知的任务不能上报为已确认任务失败或提交前校验失败；连接、HTTP 状态及取消代码不会被推断成 `TASK_FAILED`。传输超时仍为 `TRANSPORT_TIMEOUT`，不归因故障来源。后端聚合仍由服务器负责。

### 聊天模型刷新

每次列出产品路由模型前，先等待当前账号的 `harnessAccount.refreshModels` 结果。Host 使用该账号的 relay key 读取 `/v1/models`，排除已声明的媒体生成模型，并在适配器读取配置前同步非空聊天结果。并发读取共享同一次操作。成功返回空列表时不展示任何聊天模型，即使旧 profile 仍保留配置；读取不可用时返回目录失败，不把旧模型显示为当前可用。其他提供方路由保留原有的列表行为。

同一次刷新通过 `GET <base>/api/status` 读取 `data.client_model_config`，字段为 `schema_version: 1`、`default_chat_model` 和 `model_order`。明确排序的模型优先展示；未指定排序的聊天模型保留 `/v1/models` 原有顺序。旧后端可以省略该配置，此时不应用后台偏好；读取失败或配置畸形时保留上次有效偏好。读取这些偏好不发起模型请求，也不扩大模型权限。

status 中独立的同级字段 `client_model_presentation` 采用 `{ schema_version: 1, models: { [exactModelId]: { description?, badge? } } }`。两个可选纯文本字段分别覆盖两个模型选择器的说明和标签：缺失时继承本地说明，`""` 隐藏对应字段。最多接受 256 个型号，精确 ID 最多 255 个 UTF-8 字节，说明最多 500 个 UTF-16 单元，单行标签最多 32 个。说明保留换行；标签拒绝 LF、CR、NEL、LS 和 PS。未知字段、null 或畸形条目使展示文档整体无效，但不影响有效的排序和默认偏好；读取失败时两份文档各自保留上次有效值。缺少展示字段或空映射会清除旧覆写。上次有效值绑定精确后端、账号和本地登录 token，包括另一个共享会话文件的 Host 提交的变化；同一次登录内续期上游 access token 则保留这些值。仅当前授权的聊天 ID、且属于配置产品提供方时，通过 `api-session/model-presentation` 获得展示文字；其他路由继续委托原处理器。仅展示变化也会发出 `api-session/model-catalog-changed`。文字不改变路由、能力、价格、模型 ID 或模型请求。

新产品 profile 启用 `followPolicy: true`：默认值仅在当前账号已授权的聊天列表中跟随后台偏好。默认模型为空、不可用或属于媒体模型时，回退到排序后的首个可用聊天模型。手动 `saveSelection` 成功后停止跟随策略；已有手选默认值及会话内模型选择保持不变。[默认模型服务](../../core/agent-default-model/README.zh.md)负责选择的持久化。

模型 `input` 缺失或为空时，仅在安装目录中精确相同的模型 ID 具有一致的非空输入声明时继承能力。已确认的产品别名 `yunshu-flash` 在没有精确声明时继承 `deepseek-flash` 的输入能力；其他别名不作猜测。发现操作只读取同一设置命名空间内的安装提供方目录，不联系其端点。明确的非空输入声明和其他模型设置在刷新及账号模型列表变化时保留。未知或能力冲突的 ID 不推断图像能力；继承的图像声明描述目录信息，不表示已验证中转请求。

产品路由使用网关的 Chat Completions 格式：输出上限通过 `max_tokens` 传递，系统指令保留 `system` 角色，请求不发送 `store`。刷新保留其他兼容设置和逐型号覆盖。可选推理控件必须有该精确模型的支持声明；仅凭模型别名不推断推理格式或强度范围。未声明的上下文和输出能力保留适配器可配置的本地工作预算，不代表已经核实的上游限制；即使聊天没有选择显式上限，SDK 仍会发送按估算剩余上下文约束的本地输出预算。

启动和每 60 秒的定时器复用同一刷新操作。登录、退出及本地会话过期在状态提交后立即通知模型选择器；模型发现保持异步，不延迟登录。成功刷新时，可用模型 ID、排序或实际默认型号变化会发出通知；内容不变的读取不发通知。登录变化和退出会取消旧发现；提交前检查登录代次、已存会话身份、后端和有效期。卸载会取消并等待未结束的发现操作。界面可以请求新目录，无需等待定时器。公开定价仍用于描述媒体参数，账号模型端点决定其聊天列表；已声明或已选择的模型仍可能被上游的权限或计费校验拒绝。

### 充值

`POST /credits/api/recharge/wechat` 接受以元为单位的整数 `amount`，使用当前账号的 access token 创建一笔 Native 订单。响应提供 `outTradeNo`、`amount`、换算后的 `points`、`expiresAt` 和 `qrCodeDataUrl`；原始 quota 不是积分。提交订单前必须取得当前状态参数进行换算。下单结果未知时会明确报告，不自动再创建一笔订单。

`GET /credits/api/recharge/wechat/order?outTradeNo=...` 查询同一账号的订单。Host 原样转发后端状态，不设置别名，并附加换算后的积分。客户端将未知状态报告为待人工核对，不宣称支付成功。支付回调直接进入部署 API，由其负责给账号入账；产品仅在确认支付后刷新实时余额。

### 使用量分析

`GET /credits/api/usage?start=<seconds>&end=<seconds>` 返回当前登录账号按小时和模型汇总的用量。两个参数均为包含端点的正整数 Unix 秒，完整区间最多为 31 天。客户端先选择显示时区，再将自然日换算成秒。重复参数、账号选择参数和其他查询参数均被拒绝。

成功响应使用额度封装 `{ ok: true, payload: ... }`。payload 包含 `rows`、`start`、`end`、`asOf`（读取时刻的 ISO 时间）和 `delayMinutes: 0`。每行包含 `timestamp`、`model`、`billingRecords`、`consumedPoints` 及 `totalTokens`。Host 按小时和模型归并消费账单记录；零延迟字段表示不再等待旧聚合导出，不保证新扣费立即出现。消费记录数不等于请求数，单独记录的退款不从此处扣减。

Host 先使用 `/api/user/self` 核对产品会话中的账号，再通过 `/api/log/self?type=2&p=1&page_size=100` 读取选定区间的全部分页。它校验分页、账号身份、quota、token 字段及 JSON 字符串 `other`。失败、不完整或不一致的读取不会产生部分结果。管理员 token、账号搜索及部署凭据均不能替代当前登录账号。

实时 `/api/status` 读取提供 `quota_per_unit` 和 `usd_exchange_rate`。积分按 `quota / quota_per_unit × usd_exchange_rate × 1000` 计算，两个后端参数均没有写死的回退值。换算设置缺失或无效、源数据不可用或无效时，返回 `{ ok: false, code, message }`，不以零值替代。客户端负责可见错误提示和重试，读取不可用时保留之前的显示。

使用量读取共用本机来源校验、`timeoutMs` 和包含完整部署前缀的 `newApiBaseUrl`，仅使用当前账号的 access token。服务不可用时，产品不读取缓存 quota 或其他账号的余额。

聊天模型积分读取使用每个已提交 assistant 尝试的精确网关凭据，以及当前账号的 `/api/log/self?type=2&request_id=...` 记录。它核对 `/api/user/self`、凭据端点、账号和请求身份，再用实时状态参数换算已结算 quota。历史凭据缺失或来自其他网关时显示不可用；账单记录缺失时保持待结算，不捏造零值或部分合计。该金额只涵盖所选会话自身的模型尝试，不含图片／视频工具、独立提示词帮写及单独的子会话。读取不会提交模型请求，也不会根据 token 或账号余额差额推测消费。

经过身份验证的 `GET /credits/api/chat-usage` 接受一个 `session_id`、可选的正整数 `turn` 及可选的当前 `account_id`，拒绝重复、未知或携带权限的参数。Host 仅从自己的存储读取已附着 Session 的 `chatReceipts` 投影。该 Host 专用折叠从已提交事件恢复请求回执和轮次状态，不保留消息内容，也不增加 Session 事件。尚未结束的轮次为待结算；Session 查询服务、附着对象或投影缺失时为不可用。成功 payload 包含 `scope: 'chat-model'`、`status`、`accountId`、`settledRequests` 和 `totalRequests`，仅 `settled` 包含有限非负的 `points`。登录身份变化时，在响应前丢弃在途结果；显式指定旧 `account_id` 也会被拒绝。

相同选择共享登录所有的读取。已验证的账号／status 上下文及展示合计使用 `chatUsageCacheTtlMs`（默认 5,000 毫秒）；精确已结算回执 quota 使用可配置的 `chatUsageSettledTtlMs`（默认一小时），未结算空缺使用 `chatUsagePendingTtlMs`（5,000 毫秒），失败读取使用共享冷却。因此短时展示刷新不再重新扫描全部历史账单。换算参数独立刷新，回执缓存到期后仍会核对后续账单调整。缓存身份包含完整后端、账号和本地登录代次；同登录内轮换 access token 不会混入其他账号。所有有效期使用单调时间。滚动工作池遵守 `chatUsageConcurrency`，不会为全部历史回执一次创建排队操作。

账号 GET 共用 `accountReadConcurrency`（默认 2）、每登录的 `accountReadMinIntervalMs` 间隔（750 毫秒）及 `accountReadFailureCooldownMs`（10,000 毫秒）。并发的相同 GET 共享解码结果；取消一个观察者不取消其他等待者。429 使同一登录范围的各路由一起冷却，并保留更长的 Retry-After；HTTP 日期优先使用响应 Date 计算。排队可取消，退出会取消旧登录任务。`timeoutMs` 限制实际发出的每个 HTTP GET，不计算排队等待。调用者负责一次获授权的 401 续期；调度器不再增加续期循环。状态、重试等待、网络、超时、权限及响应格式错误分别保留。相同 request ID 的独立消费行全部计入；账号、完整分页及安全金额仍需校验。

当 status 的 `data.usage_receipts` 声明 schema 1、精确的 `POST /api/log/self/batch` 路径和受支持的限制时，聊天回执改用该只读批量查询。请求只包含 `request_ids`，同时遵守声明的条目数（最多 100）和编码后 JSON 字节上限，并共用账号调度、唯一 401 续期所有者和逐回执缓存。没有能力声明时保留受控限速的旧 GET；已声明的 batch 失败不会改成大量单条 GET。匹配的各条消费记录全部累加。批量结果携带 `amountBasis: 'consumption-logs'`、`refundStatus: 'unknown'` 和 `settlementStatus: 'unknown'`，其中 `settled` 仅表示所选回执全部查到记录，不代表最终净计费。`not_found` 返回不可用且不带积分，不能据此认定免费生成、失败、等待结算或已退款。

### 提示词帮写

`POST /credits/api/prompt/assist` 仅接受 `{ accountId: string, sessionId: string | null, expectedSelection: { provider: string, model: string, reasoningEffort?: string } | null, kind: 'image' | 'video', prompt: string, instruction: string, references: string[], generation: Record<string, string> }`。Host 将 `accountId` 与有效产品会话比较，不匹配时在查询任何模型前返回 `ACCOUNT_CHANGED`；账号及模型选择标识不进入提示词正文。当前原稿、修改意见、生成参数，以及按上传顺序排列、带原文件名的 `@图片1` 素材标签构成模型输入；同一标签紧邻对应图片字节，并保留在私有请求记录中。PNG、JPEG 和 WebP 参考图必须是现有本机 `ma_` 资产；任意 URL、视频，以及客户端选择的路由或凭据均被拒绝。图片以内联聊天图像内容发送。标有其他账号的上传在调用前被拒绝；没有账号标记的旧上传保留原有本机行为。成功的额度响应封装在 `payload` 内包含 `{ prompt, model }`；失败包含稳定的 `code`，绝不返回上游响应正文或异常。只有原稿、账号、聊天及模型选择仍匹配时，客户端才将候选写入可编辑的创作提示词；请求失败时保留原稿。帮写不会提交媒体生成。

帮写使用当前聊天持久化的模型选择，没有明确选择时使用当前聊天默认模型。Host 通过同一聊天目录解析选择，要求配置的产品提供方及精确模型，并按该模型声明的图片输入能力校验参考图。浏览器 `expectedSelection` 用于发现过期请求，不能授权路由。服务缺失或模型不可用时明确报错；不支持图片的选择返回 `PROMPT_ASSIST_VISION_REQUIRED`，不自动换用其他模型。已知视频模型返回 `PROMPT_ASSIST_CHAT_REQUIRED`，要求用户选择聊天模型。旧配置 `promptAssistantModel` 和 `promptAssistantVisionModel` 仍可接受，但不决定模型。每次生成前，Host 还使用当前账号的中转 key 查询 `/v1/models`、排除声明的媒体生成模型和被网关误标端点的已知视频模型，并在发送前及接收候选前复核本地聊天模型和登录身份。随后使用同一 key 调用 `/v1/chat/completions`。使用 `deepseek-flash`、`deepseek-v4-flash` 或 `deepseek-v4-pro` 直接写稿时，通过文档规定的 `thinking.type` 开关明确关闭内部思考；聊天模型及其持久化选择保持不变，但聊天推理强度不作用于这项独立写稿任务。其他模型不携带 DeepSeek 专用字段。会话过期、未登录或缺少中转凭据时停止请求，部署 key 绝不作为回退。后台续期 token 时，只有上游确认相同账号 ID，才保留中转凭据。

请求 JSON 上限为 32 KiB；原稿最多 7,000 字符；修改意见最多 2,000 字符；参数摘要最多 16 个字符串条目，键最多 64 字符、值最多 256 字符。必须至少提供原稿、修改意见或参考图。最多九张不同参考图，合计不超过 12 MiB，单张不超过 6 MiB；MIME 与图片签名必须匹配。生成响应正文及账号目录上限为 64 KiB，最终提示词上限为 7,000 字符，`promptAssistantMaxTokens` 控制生成 token 上限，默认 8,192，接受 512 至 16,384 的整数。`promptAssistantTimeoutMs` 为整个操作提供独立于其他 API 的统一截止时间，默认为 60,000 毫秒，接受 1 到 120,000 毫秒的整数；断开连接或插件 dispose（资源释放）会取消上游工作，dispose 等待请求结束。不自动重试上游请求。发出聊天生成后，超时、传输故障、取消或上游报错均返回 `PROMPT_ASSIST_RESULT_UNKNOWN`，表示结果未知且可能已经计费。无效的生成数据同样提示可能计费；用户应先查看用量，再决定是否重试。模型目录阶段失败时尚未发出聊天生成。

调用模型前，Host 将账号 ID、聊天、所选提供方/模型/推理强度、实际采用的思考开关、token 上限、准确的系统和用户文本，以及参考图元数据保存到 `stateDir/prompt-assists/<random-request-id>/request.json`。`prompt-assists/references` 下按内容寻址的图片文件，为每个 SHA-256 摘要保留一次不可变字节；普通上传可能覆盖资产 ID，因此不足以重建请求。目录权限为 `0700`，文件为 `0600` 且以独占方式创建。`outcome.json` 保存经过校验的候选或安全失败码、是否已发出聊天生成，以及可用时的私密 HTTP 状态、后台请求 ID 和有界结构化错误字段。可解码的生成响应还记录识别到的结束原因、最终文本与思考的字符数，不保留思考原文。当前中转 key 和凭据模式会被移除，不保留自由文本上游正文；浏览器响应不含这些诊断。请求 ID 可关联后台报错页中的转发失败。输入记录失败会阻止发送；结果记录失败返回 `PROMPT_ASSIST_RESULT_STORAGE_FAILED`，表示可能已经计费但候选不可用。崩溃可能留下没有结果的请求；记录保留到部署者主动删除，不自动清理。这个独立媒体流程不添加 Session 格式或 agent loop（智能体循环）行为。

### 创作内容发布

`GET /credits/api/creation/content` 将部署后台的公开文档转发为 `{ ok: true, payload }`。`GET` 与 `HEAD /credits/api/creation/assets/:id` 转发不可变的 `cc_` 内容哈希图片和视频，支持单个字节范围读取。这些读取校验来源，使用 `newApiBaseUrl` 与 `timeoutMs`，不发送账号或部署凭据，拒绝上游重定向及不符合预期的 MIME 类型，文档上限为 5 MiB，媒体上限为 100 MiB。连接断开或插件卸载会停止传输，卸载等待操作结束。错误仅公开 `CREATION_CONTENT_UNAVAILABLE`，绝不返回上游正文。[创作内容读取器](../../client/creation-content/README.zh.md) 负责文档校验、刷新及使用方状态。

### 公告

已认证的 `GET /credits/api/announcements` 从 `newApiBaseUrl` 下现有匿名 `/api/status` 读取公告，不发送访问令牌、中转密钥或 Cookie，也不跟随重定向。仅返回 `{ ok: true, payload: { enabled, items } }`；每条包含 `content`、`publishDate` 与可选字符串 `extra`。公开开关控制可见性；启用后的空列表及旧配置的 null 列表仍为空。保留 API 返回的顺序，包括未来发布时间；读取器不负责定时发布。尚未支持、HTTP 失败、数据无效和传输失败分别保留为安全错误，不伪装成空公告。完整状态响应最多 1 MiB。请求沿用 `timeoutMs`，在断开或卸载时停止，登录周期变更后丢弃结果，不缓存公告。侧栏[公告对话框](../../client/ui-settings-general/README.zh.md#announcements)将所有内容字段作为文本展示。

### 客服

Host 认证的 `GET /credits/api/customer-support` 独立于产品登录，从匿名 `/api/status` 实时读取 `data.customer_service` schema 1。专用 `enabled`、`qr_code_url`、`title` 与 `description` 转为 `{ ok: true, payload: { enabled, qrCodeUrl, title, description } }`；禁用或空二维码会清空全部展示字段。旧 API 返回 `CUSTOMER_SUPPORT_UNSUPPORTED`，绝不复用登录 `wechat_qrcode`。启用后的文字作为纯文本，拒绝控制字符，标题和说明分别限 64 与 256 个 UTF-16 单元。二维码 URL 限 2048 个 UTF-8 字节，仅接受不含凭据的 HTTPS 或精确 `/api/creation/assets/cc_<sha256>` 路径，后者保留完整部署前缀；拒绝 SVG、其它协议及相对路径。Host 只拉取状态，不拉取配置的图片 URL，也不转发访问令牌、中转密钥或 Cookie。读取沿用公告的 1 MiB 上限及生命周期，超时、网络、不可用和无效响应分别返回。弹窗重试时读取当前设置，不保留先前二维码。

### 实时生成活动

经 Host 鉴权的 `GET /credits/api/generation-performance` 提供当前登录的有界进程内计时：实际模型尝试耗时、首个非空思考与正文分别耗时、所选推理设置、工具执行耗时。不保留请求、结果、思考正文、本地路径或凭据，不修改模型参数，也不把并行区间相加冒充端到端时间。`generationPerformanceMaxRecords` 限制内存记录数量；设为零关闭采集。

生成统计独立于桌面在线状态和网关调用日志。Host 依据真实运行归属采集：忙碌的根聊天、其子 Agent 和拥有的创作后台任务共用一个聊天标识；一个八段项目分别计为一个项目、八次提交尝试。结构化创作回调区分准备、提交、受理、排队、上游生成、保存、本地剪辑和结果未知。工具返回后台运行不代表原聊天的创作已结束。本地操作中断不能证明已受理的上游任务停止。视频分段保留私有、可选的 UUID 尝试标识；新执行在提交前持久化，显式恢复在查询前补齐旧记录缺失的标识，沿用原尝试且不再次 POST。读取旧清单不会迁移记录，也不会生成在线活动。

上报要求当前登录的原生在线心跳已成功确认 UUID，并且匿名状态文档明确声明 `client_activity_workload` 能力。完整、无内容的快照使用当前交互登录访问令牌，保留完整 API 前缀发送到 `/api/client-activity/workload-snapshot`，携带单调递增序号，结束观察保留到确认接收。聊天、项目和任务分别计数；未采集、未知或过期绝不解释为测得零。JSON 不含提示词、模型详情、进度文本、路径或凭据；统计不触发登录续期，访问状态不确定时暂停发送。`generationActivityMinReportIntervalMs` 合并状态变化，默认 1,000 毫秒；`generationActivityReportIntervalMs` 更新活动观察，默认 30,000 毫秒，均使用单调经过时间。旧 API 只接收定期能力读取，支持新协议后自动恢复采集。缺少持久任务标识时将任务采集标记为不可用。完整快照最多 256 行、256 KiB，超过上限暂停上报，不截断计数或干扰生成。运行状态读取失败会暂停更新新鲜度，直到完整读取成功。计划分镜绑定和独立本地操作观察明确标记为未采集，不用宽泛的保存或剪辑阶段虚构这些维度。

### 聊天创作计划

聊天图片生成最多等待 `imageForegroundWaitMs`（默认 3 秒）以直接返回快速结果，随后返回当前聊天拥有的后台任务及已登记的计划/操作坐标。`job_output` 展示实际准备、参考图上传、本地排队、上游受理生成及保存阶段；完成结果保留单调时钟阶段计时。本地取消不会宣称上游已取消。持久调用登记阻止同一已记录工具提交在并发或重启后重复 POST；新的来源/调用身份仍独立于之前结果未知的操作。

媒体定价与当前账号组并行读取。`mediaCatalogCacheTtlMs` 将定价复用限制在 30 秒以内；no-store/no-cache 和 Vary:* 禁止复用，请求头、登录和 API 作用域防止串用，每次查询另行检查账号权限。参考图全部校验后才有界上传（`imageUploadConcurrency` 默认 2）。下载使用 `imageDownloadConcurrency`（3），保留输入顺序并遵守 `imageDownloadMaxBytes`；失败后已保存的原图仍可恢复。这些本地限制不提高网关生成并发，也不保价。

生成操作保留宿主指定的 `source`：已记录的工具调用为 `chat`，手动表单为 `ai-creation`。已确认的聊天任务不阻止 AI 创作，AI 创作的未结提交不消耗聊天请求的视频作品次数。两个入口共享账号并发容量。每个可信聊天生成请求创建独立操作，即使复用计划或提示词，先前运行中或未知的操作也不锁住新请求。旧操作保留缺失来源和原回执。旧视频项目编号或工具调用来源可以确认聊天归属；其余未知旧任务继续保留面板保护。两个入口都不根据标题或提示词猜测归属。

技能注册服务可用时，内置 `yunshu-video-director` 技能使用 [cinematic-director](https://github.com/wuwangzhang1216/DirectorSKILL) 与 [video-storyboard-gen](https://github.com/anyhui/video-storyboard-gen-skill) 的精简摘录和适配内容，指导剧情、走位、连续性、参考素材重构、分镜、对白及字幕。[固定来源及适配说明](third-party-notices/sources.json) 和两份完整 MIT 许可随包分发。生成时不运行社区脚本，也不加载整套参考库。简单单片描述直接调用 `generate_video_project` 并使用 Host 的真实默认参数，不增加目录或编导技能的模型往返；复杂时间轴和编导任务使用目录及技能。旧 `generate_video` 保持兼容。明确的剧情或连续人物创作使用显式计划，长视频仍使用该原生项目工具。原生工具负责校验、提交、轮询、下载、剪辑、发布和恢复。画面切换不必各自生成一段计费视频。不强制额外生成参考图、多个备选稿或单独请求规划模型；工作流程不能控制上游渲染耗时。

剧情、广告和多参考图视频稿采用六部分中文结构：剧情概述；每份真实素材的职责及采用、排除内容；稳定的人物关系与场景风格；包含动作、运镜、对白时间窗、音效和配乐的连续分镜时间轴；连续性要求；禁止项。分镜沿用用户提供的图片编号。明确要求如“不要字幕”优先；台词无法在指定时长内自然说完时，必须指出冲突，不能静默加速。简单请求仍保持简短。这份共享指导不增加规划生成请求，也不要求模型编写拼接代码。 工具明确报告无法关联真人请求、尚未提交时，属于本地检查失败；agent 不能据此推断服务器临时不可用，也不能承诺等待、换聊天或更换生成工具可以修复。

共享编导指导要求聊天和视频 AI 帮写将平台或上游故障概括为安全中文，不复述 HTTP 响应、诊断 JSON、代码、堆栈、内部路径或凭据。原生图片和单段视频的工具描述也附带同一份简短规则，覆盖未加载编导技能的聊天调用。已确认的登录、产品积分、文件校验及取消失败保留可操作的恢复说明。付费结果未知时，先检查已有任务与产物再决定是否重试。原生图片与单段视频的失败回执在既有状态和诊断消息之外保留可用的稳定 `code`，产品界面据此区分未知结果，不解析上游文字猜测。这些指导保留真实工具结果和必要协议字段，也不限制用户明确要求的软件或代码诊断。错误摘要区分已观察到的连接、超时、校验、权限、限流、服务不可用及上游任务失败。连接中断、超时和原因未知的失败不能证明是本机、网络、平台或上游的问题。

独立的 `yunshu-minimax-h3` 技能依据[官方提示词指南](https://github.com/MiniMax-AI/MiniMax-H3/tree/main/skills/h3-prompt-writing) 提供本地编写的 H3 格式指导，不重新分发官方技能原文件。聊天仅在为 MiniMax-H3 编写提示词且确有需要时加载它。视频 AI 帮写仅当 `generation.model` 精确等于 `MiniMax-H3` 时加入同一份格式指导，与所选聊天模型无关。指导分别描述带标签的对白原文、环境声和背景音乐，保留对白与画面文字的原语言。用户可见的创作要求、人物设定、素材说明、分镜、场景、运镜、动作和提示词默认使用简体中文，除非用户明确要求其他输出语言；英文草稿不改变这个默认值。协议字段、标签和资源标识保留原拼写。其他视频模型只接收共享编导指导，图片帮写接收同一语言规则，不接收任何视频指导。选择过程不下载在线指南，不请求翻译，也不增加聊天生成请求。

`list_image_models` 读取当前账号获准使用的图片目录，不提交生成、不上传参考图，也不估算价格。它将定价及用户组能力与账号最新模型列表取交集，并在返回前复核发起读取的登录身份。规格字符串保留已发布的像素尺寸或宽高比原拼写；命名分辨率档位保持独立。缺少菜单时不提供可选值，未验证型号仅暴露已声明菜单与 Host 的保守限制。结果也描述 AI 创作已有控件；调用方仅传递 `generate_image` 接受的字段。鉴权、权限、限流、超时、连接及服务不可用都保留为安全的读取失败，不伪装成空目录，也不使启动失败。结果不包含凭据、请求头、供应商路由或原始异常。

`update_creation_plan` 保存完整的图片或视频创作描述、稳定人物设定、有明确标识的参考素材，以及包含镜头、场景、动作、对白原文和字幕指示的有序分镜。每份计划包含 `kind`、`title`、`brief` 和 `shots`；每个镜头包含 `id`、`order`、`title` 和 `prompt`。镜头标题仅标记计划，不代表要求画面文字或字幕。修改时明确指定 `plan_id`，不能移除已有生成记录的镜头或图片素材。源路径只描述参考资料，不授权读取或预览任意文件；空来源表示尚未生成的素材。规划不请求上游。`generate_image` 和 `generate_video` 接受 `plan_id` 与 `shot_id`；`generate_video_project` 接受 `plan_id` 与有序 `shot_ids`，与实际支持的片段一一对应。`generate_image` 也可以用 `asset_id` 代替 `shot_id`，生成已有的图片素材，包括视频计划中的人物参考图。真实输出归属该素材及引用它的人物，不显示为完成的镜头或成片。关联缺失、不匹配、已在运行或提交结果未知时在计费前拒绝。未提供计划的调用创建自己的最小记录，因此聊天生成成功后仍能找到产物；调用不会隐式选择最近的项目。

图片重构和后续视频生成可以使用已上传的 `ma_` id，或同一明确计划内实际生成的图片产物 id、路径。Host 只读取该账号、聊天和工作区的准确记录，验证已保存图片，并将有界字节物化成本机上传引用，再执行常规提供方校验。因此产物目录位于工作区外时仍可复用，不新增文件系统读取根。`asset_id` 是计划标识，不是提供方引用 id；预览 URL 和任意文件路径不能作为图片参考。原有工作区视频参考仍执行通常的文件权限校验。

Host 将普通文生图、图生图的新产物标为“成图”，图片计划的产物也属于此类；为视频计划中已校验的图片素材生成的图片标为“分镜图片”。提示词、文件名和调用方传入的标签不能证明用途。恢复原任务时，按同一归属操作不可变的计划类型和素材关联重建角色，允许的计划修改不会改变它。无法分类的旧操作和通用媒体下载保持未标记；分类不增加生成权限，也不增加 Session 字段。

有 Agent 的原生 `generate_image` 调用必须先确认本次执行归属已记录的真人请求，之后才读取账号、准备参考素材或建立生成记录。仅画图的真人请求不需要视频生成额度；嵌套 PTC 调用继承其不透明父 token 捕获的归属。纯跨聊天消息或任务通知触发的轮次不能继承旧真人请求，也不能自动付费生成图片。手动 AI 创作与已有无 Agent 调用保留各自的授权路径。

`generate_image` 可直接编辑当前聊天用户附件中的图片，使用准确的附件 id 或投影后的只读路径，无需先复制到工作区。附件服务验证已保存字节；其他聊天图片及任意附件路径不授予读取权限。可读工作区图片仍执行通常的路径包含和文件检查。Host 将这些有界图片物化为私有 `ma_` 引用，再通过当前账号的中转 key，在完整配置的 API 前缀下向 `/v1/images/edits` 发送带 `image[]` 的 multipart 编辑请求。所选图片模型必须声明编辑能力；仅支持文生图的模型不会被静默开启编辑。

`yunshu-internal-gpt-image-2` 使用聊天与 AI 创作共用的独立任务合约。Host 在上传任何字节前验证最多六张已授权的 PNG/JPEG/WebP 参考图，每张不超过 10 MiB。随后通过已鉴权的 `POST /v1/uploads/images`，用 multipart 的 `model` 和 `file` 逐张上传，再把经过验证、位于 `files.toapis.cn/uploads/` 或 `files.toapis.com/uploads/` 下的 HTTPS 回执 URL 作为 `reference_images` 提交给 `/toapis/v1/images/generations`。生成携带 `model`、`prompt`、`n: 1`、可选的 `reference_images`，以及已声明的 `resolution` 档位（`1k`、`2k` 或 `4k`，不区分大小写；省略时默认为 `1k`）。目录将档位与像素尺寸分开提供；不支持的档位在上传或生成前拒绝。只有实时定价 `size` 菜单明确发布的比例才以 `size` 发送；旧目录没有此声明时不展示比例控件。像素尺寸和不支持的 OpenAI 输出参数会在上传或生成前被拒绝，显式张数必须是模型上限内的安全整数。分辨率档位不保证输出的精确像素尺寸。回执要求 MIME 与大小匹配、id 非空，URL 不含凭据、查询或片段。两条路径都保留部署前缀，只使用当前账号的中转 key。文件无效、上传失败或回执无效时，提示原始文件名并在生成前停止。上传和生成均不自动重提；普通 OpenAI 编辑保留原 multipart 路由。

图片工具提交另保留私有 `image-invocations` 领取记录，键由后端、账号、登录指纹、聊天／工作区及 Host 捕获的真人来源／根调用／子调用坐标组成。原子排他发布只允许一个竞争者领取，生成前先提交原创作计划与操作关联。并发或重启后的同次调用返回原坐标；关联前崩溃会保留未知的占位，不能据此重新 POST。独立真人请求及分别要求的工具调用即使提示词相同，也保持独立。记录不含提示词或凭据，不提供释放未知生成后重试的入口。

单次图片与视频生成在后续轮询前持久保存原相对路由、模型、后端指纹、请求和任务编号，以及可用的生成来源。本地执行器仍在等待时，排队、处理中保持生成中；执行器停止后，原任务转为可查询的未知状态。临时查询、下载或保存失败时保留已受理任务。校验账号、聊天及工作区归属的 `POST /credits/api/creative/image/recover` 与 `/video/recover` 只恢复原任务 GET 查询，不再发送生成 POST。对应 `query_image_task` 和 `query_video_task` 工具可列出未确认回执，或查询准确的原操作。没有任务编号时保留未知状态，后端变化时拒绝查询，同一恢复操作互斥，确认终态前阻止重复付费提交。图片使用 `imageSubmitTimeoutMs`（180000）、`imageTaskTimeoutMs`（600000）、`imagePollIntervalMs`（2000）和 `imageQueryRetryLimit`（2）；视频对应配置默认为 180000、900000、6000 和 2。即使显式配置更低，视频提交等待也不低于 180000 毫秒。查询同时受 `timeoutMs` 限制；重试预算不重试生成提交。

聊天视频生成归属原始人类请求。创作需求接受普通口语和礼貌请求，未指定数量时默认一条成片；明确指定数量时保留要求的总量。时长、机位切换和模型数量不增加作品次数。状态查询、检查、取消、继续原项目以及无法识别的需求不授予生成次数。模型填写的计划、改版和质量检查不能增加额度。用户的普通确认与参数补充继续同一请求；用户明确修改成片总量时修订该上限，之前已安排的作品继续计入其中。`generate_video` 与 `generate_video_project` 跨计划共享持久计数；一个项目只占一次尝试，不按内部片段数量计数。超额尝试在上游提交前拒绝。已关联项目的查询与恢复保留原任务。仅有准备记录、没有获准操作、已受理任务或已保存产物的项目，不能通过恢复获得生成许可。计划及镜头编号描述内容，不是提交身份。私有操作在提交前保存原始人类消息、根工具调用事件序号，以及独立原生或 PTC 调用编号；旧记录使用日志中匹配的操作或项目编号核对。无法归属的旧任务保留原有未知状态，不占用后续人类请求的作品次数；准确的原提交仍禁止重放。提供方调用编号可以跨消息或步骤复用，已记录的调用序号区分这些提交。后台项目返回本次请求尚待安排的作品数量，仅在明确要求的作品全部准入后结束聊天回合；并发不会扩大这个数量。

原生聊天视频工具默认使用精确型号 `MiniMax-H3` 与 `768P`，不受目录顺序或聊天推理模型影响。用户要求的受支持更高档位仍可选择，`768k` 简写对应 `768P`。原始人类请求明确指定的分辨率仍须通过能力校验；模型填写的参数不能静默提高 H3 默认档位。型号标识中的 `480p` 或 `720p` 本身不代表用户要求该输出分辨率。独立创作页保留其明确选择的控件值。

使用其他视频模型前，必须先为其完整片段计划取得免费的账号报价，再让用户实际选择。报价使用网关真实的原生参数与计价，并计入所需作品数量；并发不会增加作品数。目标价格缺失或无法核实时阻止新增生成。受支持的 H3 备选方案也能报价时，选择卡提供 H3、目标型号和取消。H3 报价已确认不可用时，仅保留已报价的目标型号与取消，并说明原因。关闭卡片同样取消。等待回答期间，已展示报价变化或过期时必须重新选择。

对于已经报价选择的模型，每次新增付费提交前，Host 重新核对发起账号、原请求、取消状态，并取得新鲜报价。完整计划、计价版本、账号绑定、币种、计费额度及金额均不变时，长时间生成等待不会使运行中的确认失效。确认仅保留在运行中的 Host，重启后不继承。原已受理任务的查询与下载仍可使用；恢复旧的非 H3 项目，不能在没有重新选择的情况下新增提交。取消后，同一人类请求不能再次发起生成尝试。

修改已保存项目之前，`get_creation_plan(plan_id)` 返回有界的完整规划字段，字段名称与 `update_creation_plan` 一致。读取同样校验账号、聊天及工作区归属，不包含执行请求或登录数据，不改变状态，也不请求上游。局部修改应先以这份权威记录保留其他人物、素材和镜头。

图片提交使用 `imageSubmitTimeoutMs`（默认 180000 毫秒），完整提交、轮询和保存使用 `imageTaskTimeoutMs`（600000 毫秒）。状态查询保留独立的 `timeoutMs` 期限（15000 毫秒），查询间隔为 `imagePollIntervalMs`（2000 毫秒），连续瞬时失败最多重试 `imageQueryRetryLimit`（2）次。生成 POST 永不重试。Host 收到响应头即保留原请求 ID，并在轮询前提交已受理的任务 ID。取消、查询中断和下载失败均保留已知任务以供只读恢复；停止本地等待不代表上游任务已取消或已经退款。未取得确切任务回执的提交仍为结果未知，不得自动重提。

已请求的独立图片调用共用 Host 队列，与视频调度分开。自动调度以十个执行为初始值，可跟随经过验证的网关池上限，最多 64；明确配置 `imageConcurrency` 为 1 至 64 的整数则设置本机上限。经过验证的较低模型上限仍生效。自动模式下，网关声明缺失或不合法时使用十个执行；显式配置仍保留其设定的本机上限。调度覆盖完整生成、观察和保存；排队取消不会提交生成，派发前重新核对账号变化。提供方原有批次保留用户请求的 `n` 与模型数量上限；并发不增加图片，原任务恢复仍只读。

图片结果返回 `submission_state`、`plan_id`、`operation_id` 及已有的任务和请求编号。不带操作编号调用 `query_image_task` 会列出当前账号和聊天中未确认的回执；提供原计划与操作编号时查询原任务并保存成品。已鉴权创作面板通过 `POST /credits/api/creative/image/recover` 启动同一条上游只读恢复。此前回执写入中断时，最终结算会原子保存最新回执。恢复仅在比较检查观测到已打开文件与原路径的身份和修改时间均保持不变时复用字节一致的图片；比较中检测到的并发编辑或替换保持原样，不作为匹配结果复用。同一聊天中待确认或未知的图片面板记录会阻止新面板提交，重载后保护仍然有效。已确认未提交的中断不会保留该锁。参见[回执归属决策](../../../.agents/notes/implemented/bug-fix/2026-10-21-image-task-receipt-recovery.zh.md)。

`stateDir/creative-projects/<project_id>/project.json` 下的私密版本化记录将计划和调用结果绑定到账号、聊天及工作区。付费提交前以仅所有者可读写的原子替换保存记录；每张图片落盘后立即登记，批量生成后续失败时仍保留前面的文件。账号或登录代次变化后拒绝晚到写入和抽帧结果。长视频任务、已保存片段、剪辑和最终完成状态仍以已有视频 manifest 为准；创作记录只关联它，不解析进度文案或复制状态。单次生成在可能计费前保存提交标记：重启后已发出但未结束的调用显示为结果未知，仅准备尚未发出的调用显示为中断。每个镜头使用最近一次明确调用的状态，旧产物继续保留；未知计费事实始终可见，并阻止对受影响镜头再次提交。显式恢复保留并发的计划修改与已保存素材。列出或打开项目均不启动或继续生成。

已通过 Host 认证的客户端读取 `GET /credits/api/creative/projects?session_id=...`，返回 `{ ok: true, payload: { accountId, projects } }`，使用不包含凭据的[浏览器类型](src/creative-types.ts)。结果同时按账号和精确聊天过滤。`GET` 与 `HEAD /credits/api/creative/media` 要求会话、项目、已登记产物 id，以及可选的抽帧索引；查询参数中的文件路径不能授权读取。媒体支持单个字节范围，拒绝缺失、符号链接文件，以及打开期间检测到的文件替换。媒体读取在开始响应前复核原账号和登录代次；读取期间退出或切换账号会拒绝尚未开始的响应。退出登录返回 `AUTH_REQUIRED`。损坏记录及存储不可用返回安全、可见的错误，不伪装成成功空列表。

每份投影包含仅根据计划计算的 `planRevision`、所属 `sessionId`、保留调用 `tasks` 及已完成和总镜头数。素材图片、生成片段和成片进入合并产物列表，按实际路径去重。计划 `durationSeconds` 可编辑，与最近提交时长 `actualDurationSeconds` 分开保存。`POST /credits/api/creative/plan` 接受 `{ session_id, project_id, expected_revision, change }`，执行有界的镜头修改、排序、人物与素材增改或明确删除，不提交生成。人物修改可同时携带新上传的图片 `assets`；图片素材与人物绑定在同一版本检查下原子保存，重复的素材 id 会被拒绝。版本过期返回 HTTP 409 和 `CREATIVE_PLAN_STALE`；正在运行的关联成员与保留执行关联受保护。`GET`/`HEAD /credits/api/creative/reference` 通过 `session_id`、`project_id` 和 `asset_id` 仅读取该计划确切的上传图片素材，发送字节前复核账号。

当前 AI 图片和视频面板请求包含 `session_id` 和 `account_id`。Host 在提交前要求经过认证的连接、相同登录账号及准确的活动工作区聊天，再通过与聊天相同的存储保留独立最小项目和实际已保存产物，不猜测最近项目。两个关联字段均缺省的旧请求保留原媒体合约。插件卸载取消并等待所属面板生成结束；上游已受理的任务仍可能继续计费。

已保存的视频片段及成片通过当前会话的沙箱和内置 FFmpeg 抽取三张真实 JPEG 预览，保存在原工作区的 `.yunshu-creative/previews`。抽帧失败标记 `previewUnavailable`，保留真实视频及其生成结果。计划和记录最多为 2 MiB，每个项目最多包含 64 个人物、128 份素材或镜头、256 次调用；列表最多读取 1,000 个保留的项目目录，项目视图合计不超过 8 MiB。不自动清理记录。人物一致性、对白内容、口型及字幕时序在实际检查成片前仍属于未验证的创作要求。

### 视频能力与参考素材

共享媒体目录优先显示定价中非空白字符串 `display_name`，缺失时回退到精确 `model_name`。显示名称不改变模型编号、权限、提交请求、计费或原任务身份。

仅当启动器将当前 profile 标识为 Desktop 时，视频提交、原任务状态读取及固定 API 成片下载才发送 `X-Yunshu-Client: desktop`。Web、CLI 和来源不明的宿主不发送此标签。它用于后端用量分析，不授予权限，也不增加设备、聊天或活动标识。目录、账户、图片及远端媒体请求不携带它；重定向仍被拒绝。缺少标签的历史请求保留来源未知。请求的视频秒数表示期望片长，与生成耗时、实际保存时长及应用前台时间相互独立。

15 个精确的 BlackRxAI 型号使用 `blackrxai-video` 网关契约，并与当前账号可见目录取交集。已声明的菜单分为固定 30 秒、15–30 秒逐整数、固定 15 秒及 10/15 秒档位，在允许时以 30 秒或 15 秒为初始选择。尺寸菜单发送 `1280x720`、`720x1280`、`1792x1024` 或 `1024x1792`；型号名称中的 `480p`、`720p` 是线路标记，不证明产物实际像素。请求仅包含网关白名单及 `n: 1`。本地参考素材先完成校验并保存私有快照，再作为重复的 multipart `images`、`videos`、`audios` 文件字段提交，保留全部已接纳素材并遵守各型号数量上限。内部快照、data URL、metadata 及额外的分辨率/比例字段不会发送到该线路。无参考素材时使用 JSON。

普通单视频在提交前持久化不含凭证的回执，并在轮询前持久化已受理的任务编号。取消本地等待、查询中断和结果未保存均保留原操作及其未确认状态。同账号、同聊天已有未确认视频提交时，面板阻止再次生成。`query_video_task` 及经过宿主认证的 `POST /credits/api/creative/video/recover` 只查询并保存已保留的原任务，不再次提交视频。创作任务卡提供相同的恢复入口。已有 manifest 视频项目继续使用原有的显式恢复流程。

视频提交和状态查询使用所选能力的 `route`；公开定价明确指定的路由优先。MiniMax-H3 使用 `POST /v1/video/generations` 和 `GET /v1/video/generations/:id`，其他视频模型保留原有协议。`data` 内的通用任务响应支持大写 `NOT_START`、`SUBMITTED`、`QUEUED`、`IN_PROGRESS`、`SUCCESS` 和 `FAILURE`。成片通过 `/v1/videos/:id/content` 读取，保留配置中的 `/harness` 前缀，并使用当前账号的中转 key。渠道的聊天测试不能验证视频生成。

视频菜单优先读取公开定价 `parameters`（字段映射或 JSON Schema 的 `properties`）中明确的 `seconds` 或 `duration` 声明，其次读取 `billing_usage_schema`。数值枚举或有限的 `minimum`/`maximum` 范围选出 1 至 3600 秒内的整数，并覆盖模型表；排他边界和 `multipleOf` 进一步缩小时长菜单。缺失、格式错误或无上限的声明保留已知模型限制；计费样例不授予时长或额外参考槽位。分辨率与 `ratio`/`aspect_ratio` 菜单使用相同的实时优先级；同一字段同时声明 `const` 和 `enum` 时取交集。已声明的 `frameRatios` 与当前比例菜单取交集。精确型号 `doubao-seedance-2-5-260628` 的首尾帧输入使用 `adaptive`：省略比例时选择合法默认值，显式冲突或交集为空则在上传或生成前拒绝。当前 H3 响应只声明未限定范围的数值秒数字段，因此保留已知的 4–15 秒菜单。公开定价列出某个模型，不代表特定账号已可用它生成。参考视频和音频输入只按准确型号的明确声明展示；未知型号匹配某个模型系列，不能据此认定支持。

明确的 `oneOf` 将 `properties.resolution.const` 或 `.enum` 与有限的 `properties.seconds` 或 `.duration` 配对。得到的 `durationByResolution` 菜单同时约束面板请求和项目规划；未列出的分辨率不可用，并且必须选择分辨率。例如，生产方可以明确发布 480P/768P 为 4–30 秒、2K 为 4–15 秒的两个分支。这说明解析器支持的格式，不表示当前 API 或尚未明确的上游支持这些组合。Host 在模型提交前拒绝不支持的组合、小数或非数值时长。

显式视频参数的 JSON 类型不符或种子不是安全整数时，生成前会拒绝请求。分辨率、比例或档位菜单为空不授予任何值；不支持的控件会被拒绝，不会从面板请求中静默移除。

本机 `POST /credits/api/assets` 按真实字节识别图片，不依赖后缀或 MIME 提示；完整解码 PNG/JPEG/JFIF/WebP/AVIF/GIF/BMP/TIFF/HEIC/HEIF，纠正方向后生成模型可用的 PNG 或 JPEG。原图上限为 32 MiB、4,000 万像素；转换后每张不超过 6 MiB，一次生成中的图片合计不超过 12 MiB。动态及多页图片明确取首帧。响应保留原文件名、实际来源格式、尺寸、转换后的 MIME/大小及转换信息；结构化失败标明对应上传，不泄露解码器异常。`GET`/`HEAD /credits/api/assets/preview?asset_id=...` 通过宿主认证及上传账号校验后提供转换后的图片，响应使用 `Cache-Control: no-store`。视频和音频仍要求 MIME 与文件签名匹配，分别限制为 32 MiB 和 15 MiB。生成请求的全部参考字节不超过 48 MiB，编码后的完整请求不超过 64 MiB。H3 与 Ark 将各自声明的参考素材放在同一个完整的 `metadata.content` 数组。Ark 条目保留 `first_frame`、`last_frame`、`reference_image` 和 `reference_video` 角色，不使用平铺首尾帧别名；已声明且选中的 `resolution`、`seed` 和 `generate_audio` 值也会发送到上游 metadata。其他线路保留原有的帧序列化方式。H3 与 Ark 禁止首尾帧和通用参考槽位混用；自适应比例需要实际图片或视频输入。媒体校验不证明上游生成质量。

两个聊天视频工具的 `reference_videos` 都接受已上传素材编号或可读的工作区 MP4/MOV 路径，`reference_audios` 接受已上传编号或工作区 WAV/MP3 路径。工作区之外、用户已授权读取的附件须先用现有文件工具复制进工作区；不能直接传外部路径、网址或附件编号。已存素材必须有当前账号的归属凭据；缺失或账号不符时，须在当前账号下重新添加。视频项目保留准备好的引用用于恢复。可选的 `audio` 请求只有在所选模型声明了对应开关时才发送提供方开关。BlackRxAI 既未保证输出音轨，也未声明音频开关：目录设置 `audioOutput: unknown`，与参考音频输入上限相互独立。消费者不能根据保留的 `audio: false` 推断成片一定静音；请求也不能强制启用未声明的音频开关。缺少 `audioOutput` 的模型保留原有 `audio` 声明。H3 固定原生音频：接受 `audio: true`，不添加上游不支持的请求字段；`audio: false` 则在提交前拒绝。

### 产物保存位置

新图片、视频、分镜片段和本地剪辑采用简短内容标题、用途、可选顺序号与 UUID 组成文件名。优先使用已保存的计划、镜头和素材标题；无计划时使用提示词短摘要。文件名过滤 Windows 保留字符与设备名，并限制在 180 个 UTF-8 字节以内。排他写入保留已有文件。恢复复用已保存路径，不重命名旧素材，也不重新提交生成；命名不额外调用模型。

组合提供可选的[产物保存服务](../../deliverables/artifacts-index/README.zh.md) 时，图片、下载媒体和单段视频在生成或保存前捕获当前目标目录。同一次操作的全部输出使用同一目标，即使期间用户更改了设置。新视频项目持久化已捕获的发布目录；剪辑仍在工作区沙箱内执行，随后由 Host 将成片复制到该目录，不替换已有文件。发布失败保留原片和暂存成片，供显式恢复，不重复已完成的付费提交。本地视频剪辑使用同一发布服务。

聊天生成在产出文件前捕获准确的 Session、当前开放轮次及根工具调用。媒体输出通过产物存储服务携带该来源；异步图片/视频回执和长视频清单保留来源，用于下载、恢复及继续发布。恢复时不会替换成查询状态的聊天或轮次。缺少来源坐标的旧记录及独立创作页任务不自动关联，之后可通过聊天中的明确展示建立来源。损坏或跨聊天的持久化来源坐标会被拒绝。

未提供该服务时，图片和单段视频继续使用 `stateDir/media`，视频项目继续使用工作区输出目录。没有发布目录字段的旧项目记录恢复时保留原有工作区行为。更改偏好不会移动已有文件或改写旧聊天路径。

### 本地视频剪辑

项目剪辑器使用桌面端提供的 `DSH_VIDEO_RUNTIME_ROOT` 目录，不搜索 PATH。付费生成前会验证两个可执行文件，并在选定输出目录实际执行一次 H.264/AAC 编码，拒绝只读或逃逸的输出目录。每个进程均经过当前会话的子进程服务和已解析的沙箱策略，不拼接 shell。输入必须是工作区内的普通文件，或项目所有者已授权的确切私有片段目录中的普通文件；私有片段路径拒绝符号链接。当前聊天附件位于工作区之外时，模型先通过现有文件工具把已获读取权限的附件复制进工作区。协议访问仅允许本地文件和管道。

剪辑保留原片，按明确的开始和结束时间裁剪，将画面等比缩放并补边到首段画布（或部署时明确指定的画布），并将尺寸取为偶数，转换为配置的帧率，并将音轨统一为双声道 48 kHz。没有音轨的片段补静音。最多 `videoEditSinglePassMaxInputs` 份输入（整数 1–32，默认 3）在同一滤镜图中完成解码画面的标准化和拼接，最终只编码一次固定帧率 H.264/AAC 成片。每份输入限制为单线程解码，并分别限制协议为本地文件和管道；更多输入保留原有的串行标准化与最终编码，限制同时运行的解码器数量。不添加转场、字幕或配乐。可选的成片时长会裁掉拼接结果的末尾，素材不足则明确拒绝。FFprobe 在成片以独占、同卷原子方式发布前核对时长；已有目标文件不会被替换。取消和超时会终止并等待受管进程范围退出，再清理临时文件。剪辑失败不会发布候选文件；已经完成的原片保留，可在后续剪辑中复用。本地进程失败在已知时附带可复制的诊断，仅包含工具、操作阶段、退出码、终止信号及中断类型；参数、路径及子进程输出保持私有。超时明确显示为超时，解析可执行文件期间的取消不会显示为缺少运行时。这项修改缩短本地拼接时间，不缩短上游生成耗时，也不验证模型生成的人声、口型或字幕质量。

### 视频项目

聊天结合完整对话理解视频意图和目标数量。Host 不再通过固定句式匹配授权生成，也不执行按消息推算的作品额度。简单生成默认准备一条成片；用户要求多条时，先通过 `prepare_video_works` 准备具体数量，每条成片获得一个 `work_id`。同一真人来源重复准备只返回原清单，不扩展或重置已提交作品。已准备清单后，用户在真实问题回答中明确增加数量时，`append_video_works` 只追加缺少的具体作品（已有一条改为三条时追加两条）。Host 为当前执行捕获这条准确回答；重复处理同一回答不会再次追加，已用于初次准备的回答也不能再加一份。原作品编号、未知操作和领取记录均保留。普通确认或查询不代表要求更多视频，目标数量仍由 Agent 结合对话理解。用户减少数量时，Agent 只启动仍要求的作品，多余的待办编号保留未启动状态；待办清单不要求必须生成。片段、分镜和并发不会增加成片数量。

两个生成入口在准备参考素材或创建视频项目前先领取已准备的 `work_id`，并在任何生成 POST 前关联原操作。并发调用、替换工具调用 ID 和进程重启都返回同一保留作品，不创建另一轮提交。确认、参数纠正和恢复复用已有 `work_id`；独立真人新请求可以准备另一份清单，即使提示词、计划或分镜相同。`pending_work_ids` 和 `remaining_works` 只描述清单里尚未启动的具体作品。已受理和结果未知的任务使用原编号查询或恢复。升级时沿用准确关联原来源的已有操作；领取记录丢失或不一致时停止新增提交。进程若在领取后、关联操作前退出，保留的准备记录不会自动重跑；结果会要求核对原调用，或由用户另行发起独立创作请求。私有作品清单 v2 必须保留初始数量和完整修订历史；历史缺失或截断时停止追加。旧 v1 清单须先校验再显式迁移，既有领取记录保持原格式。

每条顶层真人消息都建立执行归属，不依赖其措辞。对待回答 `ask_user_question` 的准确真人回答可以继续原来源；工具通知、会话转发和子代理委托不能创建真人归属。原生执行 token 和嵌套 PTC token 保留发起时捕获的来源。明确时长、分辨率和型号提示与执行许可独立，Agent 在工具输入中保留用户要求。结构化型号选择取消作用于对应作品，其它已准备作品保留各自身份。非 H3 型号仍须按当前实际提交的一件作品取得实时报价和真人选择。取消语言额度不代表模型一定准确理解新请求或数量；具体作品清单明确记录理解后安排的作品身份。

简单单片请求在没有明确计划或分镜数组时，可以省略 `total_duration_seconds`。Host 只读取一次账号可用型号，使用模型声明的默认时长；未声明默认值时使用首个受支持时长。明确的默认值非法时在提交前失败。同一已解析型号继续用于请求校验，避免为了读取默认值另走一轮模型；用户明确的时长和计划仍执行原有校验。工具返回真实后台任务。

工作区聊天可通过 `generate_video_project` 制作超过所选模型单段时长上限的完整视频。规划器先最小化计费片段数量，再最小化多余秒数：模型支持对应时长时，40 秒请求使用 `15 + 15 + 10`；仅支持固定 15 秒时生成三段，并裁剪为 40 秒。首次计费提交前，系统验证所有分镜请求和本地剪辑工具。可选分镜说明的数量必须与规划片段数相同；上传引用编号和可读工作区素材均经过当前会话校验。生成只使用当前登录账号的中转凭据，每次提交前核对捕获的账号与登录状态；退出、过期或切换登录会阻止后续新增计费。

明确提供 `shot_durations_seconds` 时，按这些受支持的分镜时长逐一执行，总和必须等于请求总时长。关联创作计划且每个所选镜头都有时长时，固定流程使用已保存时间轴；时长填写不完整时要求修正，不静默重新分段。没有明确分镜提示词时，流程按所选镜头组装已保存的场景、运镜、动作、对白原文、字幕和人物设定，添加该镜头关联的图片和人物参考（优先使用最近生成的图片），以及其所选 `asset_ids` 的视频、音频来源。所选视频或音频来源为空或不存在时，在提交前拒绝。报价与生成将同一镜头的素材和明确共享的引用按同一规则合并，不带入其他镜头的素材。兼容工具 `generate_video` 仍使用明确的参考参数；其 `plan_id` 仅关联操作，不自动带入计划素材。所有引用及时长在首次计费前校验，不额外请求规划或翻译模型，也不让 agent 编写拼接脚本。已保留项目仍恢复原先保存的完整请求。

每段请求均保留完整主说明作为共享上下文，并明确只生成当前分镜、对应时长和分配给它的台词。分镜说明补充当前镜头的要求，不替换主说明。合并后的提示词超过提供方上限时，在任何计费提交前失败，绝不截断用户原文。已有项目恢复时仍使用原先保存的完整请求。

用户要求对白时，指令区分稳定的说话人、台词原文与语言、画内发声、画外旁白、环境声和背景音乐。指令保留明确的静音要求，只在用户要求时请求字幕。H3 专属说明遵循其原生对白格式。这些均为生成要求：剪辑器不合成人声、不对齐口型，也不创建字幕轨；文件验证不证明成片确实出现了指定对白或同步效果。

项目使用已有的会话所属后台任务。启动或恢复项目返回规范的 `job_id`、`project_id` 和 `plan_seconds` 后结束本次聊天轮次，让用户在生成期间继续发送新请求。项目任务声明 `readMode: background`：即使传入 `wait: true`，`job_output` 也立即返回当前快照，运行中的快照会结束本轮，避免模型循环轮询。其它任务保留正常等待行为。最终成功结果只包含经独立验证且实际保存的 `final_path` 和片段路径。代理通过现有 `present` 工具和可点击的产物链接交付最终文件。

配置的 API 声明准确的视频队列协议后，支持的项目使用提交前已持久化的尝试 UUID，将所有授权片段入队后再观察完成状态。服务器负责持久等待、共享准入和上游恢复。能力缺失或关闭时沿用原中转接口；无法完整读取或配置冲突时，在 POST 前停止新的生成。本地 multipart 快照、本地素材编号或不支持的引用会在首个 POST 前让整个项目使用原路径，不丢弃参考素材。本轮队列支持纯文本及原已支持的持久参考 URL。回执丢失只能 GET 同一个确定的队列编号，不能再次新建或回退原接口重投。读取原队列和原网关任务不依赖新的生成能力探测或型号目录。

`cancel_video_project` 先停止并等待所属本地任务，保留晚到回执，再请求服务器取消已保存的队列编号。只有服务器确认派发前取消才报告已取消；派发冲突、结果未知和原接口任务保留原编号，可能继续运行和计费。工具不承诺上游取消或退款。普通 `job_kill` 仍只取消本地任务。

独立片段可在同一项目内并发执行。没有经过验证的网关上限时，自动调度使用四个工作槽；有可信账号池声明时可跟随至十六，明确配置的 `videoProjectConcurrency` 则设置本机上限。经过验证的较低限制仍生效。API 负责跨账号、跨用户的原子平台准入；观察到的空闲槽位不是预留。首个失败或未知片段停止新增提交，并保留已启动工作的回执与结果。显式恢复仍可按已保留的任务编号查询、下载和保存其他已受理片段；原阻塞尚未解除时，不新增生成 POST，也不拼接不完整成片。已受理任务按原编号查询，未知提交绝不自动重提。最终拼接按已保存时间轴顺序进行，不受完成顺序影响。客户端设置不能证明供应商容量，也不配置上游 key。

账号绑定提供方从已配置网关当前定价行的 `parameters["x-client-concurrency"]` 读取声明，并在发现前后重新核对发起登录。经过验证的声明包含 `schema: 1`、`atomic_admission: true`、`model` 等于所选精确型号、`scope: "shared_account_pool"`、`reservation: false`；`max_parallelism` 是安全整数，视频为 1 至 16，图片为 1 至 64。它描述实际执行的池上限，不证明供应商容量、不统计空闲槽位，也不预留服务。视频声明缺失或不合法时使用四个工作槽；冲突声明不能提高这个默认值，但经过验证的较低上限仍有效。当前账号模型列表必须授权视频型号，定价目录也必须将其标为视频。`MiniMax-H3` 使用同一契约；四个独立且已启用的上游 key 若有经过验证的十六并发池声明，自动模式可使用十六个工作槽。每次 POST 仍须经过真实网关准入。

项目记录持续无法保存时，最终 `PROJECT_STORAGE_FAILED` 结果保留已知受理任务的 `task_ids`，提示用户保留编号并在后台核对。已保存记录仍标为 `submitting` 时，结果继续未确认并禁止重提；存储失败不表示上游生成失败。

后台进度显示整体工作阶段，并按保存的时间轴为每段保留一行。每段独立显示排队或生成状态及本段累计观察秒数；另一段更新或进入最终剪辑时，保存中、已保存、失败、结果待确认和已暂停的片段仍持续可见。这些观察状态只在运行期间保留；显式恢复从原记录重建事实，按原任务编号查询。每次运行仅向普通任务输出追加一次最终分段状态汇总，完成任务清除实时进度后，`job_output` 仍保留每段结果，不按每次轮询追加日志。

每段截止后暂停观察，保留原任务编号供明确恢复。兼容的前台 `generate_video` 在取得任务编号后观察 `videoChatWaitMs`（默认 60,000 毫秒），随后返回待处理回执；聊天续查每次观察原任务 `videoChatQueryWaitMs`（默认 30,000 毫秒）。这两项配置接受 1 至 2,147,483,647 的整数毫秒，不截断提交或保存。繁忙响应没有任务编号时仍是结果未知，不能当作已确认排队，但下述网关明确确认的 H3 容量拒绝除外；失败或超时的 POST 都不会自动重提。

精确 `MiniMax-H3` 请求接受以下完整网关合同作为确定拒绝：HTTP 429 携带 `h3_account_capacity_exhausted`、`submission_state: not_submitted`、`data: null`、`retryable: false`、`resubmittable: true` 且无任务编号；或 HTTP 502 携带 `h3_upstream_auth_rejected`、`submission_state: failed`、一致的原 `id`/`task_id`、`refund_confirmed: true`、`data: null`、`retryable: false`、`resubmittable: false`。两者均将本地请求尝试结算为失败并解除该次创作锁。容量拒绝未创建任务、未收取生成费用；确定的鉴权失败保留原失败任务编号与退款确认。客户端均不自动重发 POST。失败分镜在恢复及重启后仍为失败；再次生成需要用户明确发起新尝试或新项目。其它 429/502、缺少确认字段及提交中断仍按结果未知处理。202 未知响应保留原任务编号，只通过 GET 恢复。

网关确认未外发的 H3 尝试保留原 HTTP 状态及安全业务码，并精确携带 `submission_code: h3_submission_not_sent`、`submission_state: not_submitted`、`upstream_submitted: false`、`retryable: false`、`resubmittable: true` 及一致的原 `id`/`task_id`。`billing_state` 必须是 `not_charged`，或是带 `refund_confirmed: true` 的 `refunded`。同一原任务的 GET 可在 `submission_receipt` 中提供相同证明；仅终结对应本地尝试，保留原任务和请求编号，不设置本地提交前标志，也不再次生成。字段缺失、身份冲突或旧未知尝试没有任务编号时继续保锁。查询某段时收到确定拒绝，不会因为其它片段的取消信号携带同一个错误而改变那些片段的状态。

其它图片和视频型号使用独立的 `media_submission_receipt` 证明。版本 1 将精确公开型号、媒体类型与原任务编号绑定到 `media_submission_not_sent`、`not_submitted`、`upstream_submitted: false`、`retryable: false`、`resubmittable: true` 及同一任务的 canonical GET 恢复路径。`not_charged` 只允许没有退款确认字段或值为 `false`；`refunded` 必须确认 `true`。H3 和通用媒体证明字段不能混用。完整证明将已发生的 HTTP 尝试结算为失败并保留原回执；畸形或冲突证明继续待核对，不能按普通失败解锁。任何证明均不授权自动重发。

独立的 `media_submission_rejected` 证明用于已经发送、但上游型号明确拒绝受理的请求。提交须为 HTTP 400，或原任务 GET 为 HTTP 200 且状态 `FAILURE`，同时绑定一致的原始身份、`upstream_submitted: true`、`provider_response_received: true`、唯一原因 `upstream_model_not_available` 和已确认退款。文案区分拒绝受理与原来不变的从未发送证明。普通上游 404、超时或容量错误不能证明这一结果，也不允许重复生成。

H3 原任务查询固定使用 canonical `/v1/tasks/:id` 路由。失败或取消响应只有在 HTTP 200 明确包含 `provider_terminal_confirmed: true`、一致的原任务标识和对应终态，且不存在提交或计费证据冲突时，才终结该原任务。这只确认上游结果，不代表退款，也不会触发再次生成。缺少这些证据的历史 H3 失败状态仍保持待确认。

`stateDir/video-projects/<project_id>/manifest.json` 中的私有记录仅所有者可读写，保留账号编号、非秘密登录指纹、所属聊天与工作区、原始说明和完整已准备请求、分镜计划、上游任务编号、已保存片段路径及最终状态。每次提交前以及任务编号和片段保存后均原子替换记录；记录不含凭据或上游原始响应。可选的本地 `title` 与 `shotTitles` 保留输出命名上下文；旧记录使用已保留的提示词。这些标签不会进入提供方请求。原始片段保留在私有项目缓存，供剪辑和恢复使用。每个校验完成的片段及最终成片还通过产物保存服务发布到生成前捕获的保存目录；后续片段失败时，已完成片段仍可在产物库找到。旧版仅使用工作区的项目将片段发布到原工作区的 `videoProjectOutputDirectory`。经过授权的项目读取及 `video_project_status` 会在本机补发布已有历史片段，不再提交生成请求。可重试的本机复制失败时，已授权项目继续可见并提示发布失败；恢复保存目录或原文件后刷新即可重试复制。本地剪辑先在沙箱内将成片保留到工作区，再执行发布；返回的媒体路径指向已发布副本。记录和素材不自动清理。`video_project_status` 按账号、聊天和工作区校验读取权限。进程重启后保留的是记录，不会虚构仍在运行的任务；显式调用 `resume_video_project` 会复用已保存片段并读取已知任务编号。只有清单与实际请求均选择 H3 的项目，才允许提交从未提交的剩余片段；非 H3 恢复要继续付费生成时，须提出新的生成请求并重新选择型号。没有已持久化任务编号的提交属于未知结果，可能已计费，绝不自动重提；失败的上游任务同样需要明确创建新项目，或剪辑已保留片段。

可配置 `videoProjectMaxSeconds`（默认 300）、`videoProjectMaxSegments`（32）、`videoProjectConcurrency`（省略时自动调度，后备值为 4；显式接受 1 至 16 的整数）、`videoProjectPollIntervalMs`（6000）、`videoProjectTaskTimeoutMs`（900000）、`videoProjectDownloadMaxBytes`（536870912），`videoProjectReferenceMaxBytes`（每个本地引用 20971520），以及相对于工作区的 `videoProjectOutputDirectory`（`artifacts/videos`）。任务期限分别约束单次提交、原任务查询和保存，不是生成总时限。队列查询也遵守服务器声明的最短间隔。原任务 GET 瞬时失败按 `videoQueryRetryLimit` 有界重试，耗尽后暂停观察并保留原任务，不认定上游失败或重新提交。视频内容下载的完整传输期限至少为 300000 ms，提交期限至少为 180000 ms，模型目录与状态请求仍使用 `timeoutMs`。内容读取中断返回 `VIDEO_DOWNLOAD_UNAVAILABLE`，清除未完成文件，保留已知任务供显式恢复，不再次提交。生成前，完整记录连同任务与路径元数据的预留空间必须不超过 64 MiB。这些限制在计费前生效。镜头连贯性仍取决于提供方；管线提供有序分镜说明与共享参考素材，不会承诺模型尚未生成的主体一致性或转场画面。

图片生成、单段视频提交、长视频项目和 AI 帮写仅在实际 HTTP 403 响应含网关精确错误码 `insufficient_user_quota` 时返回 `INSUFFICIENT_BALANCE`；OpenAI 错误封装还须具有网关的 `new_api_error` 或图片协议的 `invalid_request_error` 类型。上游额度不足、渠道欠费、令牌额度、普通 403 和传输故障均不表示用户余额不足。明确资金拒绝会停止固定视频流程并保留已保存片段。网关也可能在上游受理后因追加费用而返回此错误，因此未确认的提交继续保持未知状态，即使充值也不能自动重发。原生任务插件若已把错误码改为 `permission_denied`，产品无法恢复原始原因，因此仍显示通用错误。不另发余额估算或付费探测请求。

## 模型体验

### 使用量分析

#### 模型接收的内容

通过 `/credits/api/usage` 进行的使用量分析仅供浏览器读取，不贡献模型输入。

#### token 影响

使用量读取不请求模型，也不消耗模型 token。

#### KV Cache 影响

使用量分析不改变模型上下文或 KV 缓存。

### 提示词帮写

#### 模型接收的内容

提示词帮写使用所选聊天模型发起一次不流式返回的生成。视频帮写与内置聊天技能共用编导指导，包括可拍摄的剧情节奏、人物一致性、镜头、对白原文、口型及按需字幕时序；这些是生成要求，不是已验证的成片结论。系统指令及用户文本将原稿、修改意见、参数和图片视为不可信参考资料。模型返回纯文本候选提示词。每次修改都发送当前编辑后的候选及新意见，而不是隐式对话历史。模型可见输入及经过校验的结果，可通过上述私有独立记录重建。

#### token 影响

每次帮写或修改请求均按当前账号计费，生成输出上限为 2,048 tokens。原稿文字、修改意见、参数及参考图片均贡献输入用量。精简共享视频指导会贡献输入 token；H3 格式只在选择该生成模型时加入，不增加帮写请求。

#### KV Cache 影响

每次明确发起的请求都提供当前原稿和修改意见，不包含隐式对话历史。这个独立流程不管理提供方缓存。

### 视频项目与剪辑

#### 模型接收的内容

只读图片目录工具将工具声明，以及被调用后返回的精确模型控件或安全错误加入普通工具历史。通用读取卡片标明目录操作，不额外发起生成补全或隐藏的模型输入。可选的内置编导技能通过现有的、有日志的技能机制贡献目录描述，并在加载时提供编导及原生工作流程指令。视频工具（包括 `generate_video_project`）向模型上下文加入分镜规划、本地剪辑、持久状态和显式恢复说明。工具说明要求代理包含台词原文、语言、说话人及字幕要求。每段提供方提示词保留主说明，限定当前镜头，并加入按需生效的音画指令。代理必须检查实际成片，才能声称人声、口型或字幕已经出现并同步。分镜说明来自已记录的工具输入和保存的有序说明。现有任务工具通过常规日志结果呈现进度和最终路径。视频项目记录保留完整生成请求，无需改变会话格式或代理循环。创作规划工具通过常规工具历史记录结构化输入与返回的计划 id。生成调用记录明确的计划和镜头关联。浏览器项目读取与可选抽帧不加入模型输入，不请求上游，也不消耗模型 token；后续修改仍通过明确的、有日志的工具调用完成。

#### token 影响

工具声明、已加载的技能文本与已记录结果贡献常规代理上下文 token。原生工作流程不会额外调用聊天生成；计费的视频模型调用遵循已持久化的片段计划。

#### KV Cache 影响

工具声明与已记录结果遵循常规 Session 请求处理。视频生成和本地剪辑不添加隐式聊天历史，也不管理提供方缓存。

## 已知限制与延后工作

<a id="known-limitations-and-deferred-work"></a>

- 数据源按小时分组，通常每五分钟写入一次。这些汇总无法提供准确请求时刻、扣除退款的净支出、输入输出 token 拆分或实时余额账本。用量响应最多包含 100,000 条源记录；超限时明确报错。
- 视频完成只验证文件已保存及其时长，不验证台词内容、口型同步或字幕准确性。本地剪辑保留每段的第一条音轨，不混合独立的人声与配乐轨，也不保留软字幕轨。
