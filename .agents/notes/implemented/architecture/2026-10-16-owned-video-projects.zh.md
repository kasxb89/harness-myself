# Agent Note: Retain paid video submissions as owned projects

Status: implemented

[English](2026-10-16-owned-video-projects.md) | 中文

## 问题

自然语言请求的时长可能超过视频模型的单段限制。合并多次付费生成会产生部分结果、提交结果未知和本地剪辑失败等状态。进程重启会丢失实时后台任务，但这不能表示已被上游接受的任务已取消或未计费。

## 决策

额度 Host 按当前账户实际可用的模型时长规划，并在发送前保存确切的有序请求。私有项目将请求绑定至账户、调用聊天和工作区。每次提交均在发送前记录，返回的任务标识均在轮询前记录。显式恢复会查询已知任务并复用已保存片段；没有持久化任务标识的提交始终表示计费结果未知，绝不自动重复。[包参考](../../../../packages/host/credits-index/README.zh.md#video-projects)负责限制和操作语义。

现有任务服务负责实时执行，独立项目记录负责恢复，无需修改 agent loop（智能体循环）或 Session 格式。随应用提供的媒体可执行文件经过会话文件和进程策略执行；付费提交前必须在选定输出目录完成实际编码。只有经过独立检测的输出才能成为最终产物。

## 考虑过的替代方案

**让模型分别调用片段生成和 shell 命令。** 部分计费与恢复规则会变成隐含行为，而且依赖环境中已安装相关工具。

**重试所有被中断的提交。** 响应中断之前，任务可能已被接受并产生费用，重复提交可能导致重复扣费。

**把保留记录视为运行中的任务。** 已保存的 manifest 无法证明执行器在重启后仍然存活，也无法证明输出存在。

## 影响

用户可以直接请求完整时长，并继续剪辑保留的片段。生成连贯性仍取决于所选提供方，本地取消后上游任务仍可能继续计费。私有记录和原始媒体在被显式移除前持续占用存储空间。无需密钥的测试覆盖账户绑定、未知结果、恢复、实际沙箱合成及最终时长检测，但无法证明提供方的渲染质量。
