# Agent Note：创作准备与账号读取

Status: implemented

[English](2026-10-26-creation-preparation-and-account-reads.md) | 中文

## Problem

聊天消耗展示的短缓存到期后会重新读取历史回执。并发上限不能限制请求频率，共享网关限流还会拒绝余额读取。把失败的 null 结果当成成功又清除了错误原因。创作流程也会重复准备依赖，并在每次对话中临时生成常见 Office 编程步骤。

## Decision

回执身份和有效期由登录拥有的账本管理，独立于展示刷新。限速账号读取器合并相同请求，保留实际 HTTP 状态与等待信息，续期仍交给原来的唯一执行方。通过能力发现启用的只读批量查询减少初次历史读取；失败不会扩散为逐条查询。消费日志不等同于最终净结算。

图片提交身份来自捕获的账号、工作区、真实用户来源和已记录调用坐标。在上传或付费请求前先独占登记。同次提交结果未知时防止重放，但不禁止其他来源。后台任务管理本地取消和可见阶段；持久创作回执管理上游恢复。本地任务结束观察不代表上游成功或已取消。

依赖复用依据经过核对的载荷身份，而不是应用展示版本。并列安装代保留其他进程仍使用的路径。常见 Office 工具执行稳定生成与必要检查，复杂设计和修改继续使用原可编程流程。缓存复用需要相应内容及环境身份；身份无法确认时重新执行，不虚构有效性。

## Alternatives considered

**提高网关总限额。** 这不能消除重复历史查询与共享网络干扰。即使服务端隔离已鉴权读取额度，客户端仍需合并与限速。

**按提示词相似度判断重复。** 用户可以主动再次请求相同内容。已记录来源和调用坐标能够区分新请求与同次提交重放。

**返回后台编号即视为成功。** 界面响应不等于生成提速或计费完成。结果保留原来未知或待确认的上游状态。

**通过跳过文档检查提速。** 常见结构化执行减少临时编程和重复准备，同时保留格式、公式与排版验证义务。

## Consequences

旧 API 保留限速的逐回执路径，只有精确能力发现后才使用新批量接口。回执缓存有独立可配置有效期，以便读取后续调整。后台任务属于进程内记录；重启后仍以持久计划与操作坐标恢复。运行时代会占用额外磁盘，直到能够在不删除其他进程可执行文件的情况下退役。

## Verification

Loader 与本地 HTTP 测试覆盖空正文 429、Retry-After、单次 401 续期、登录切换、批量边界与失败不扩散。真实任务注册表测试覆盖快速完成、原任务恢复、取消和等待清理。Office 样例检查原生可编辑对象与公式重算；依赖样例覆盖并行进程及损坏安装。
