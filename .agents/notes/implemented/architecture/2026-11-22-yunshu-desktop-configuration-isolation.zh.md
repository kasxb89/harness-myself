# Agent Note: 云枢 Desktop 配置与应用身份

Status: implemented

[English](2026-11-22-yunshu-desktop-configuration-isolation.md) | 中文

## 问题

带有品牌名称的 Electron 窗口仍可能与上游 Harness 安装共用按包名派生的浏览器目录、单实例锁、URL 协议和 profile 配置。启动一个产品可能聚焦另一个产品，既有 profile 或全局 patch 也可能替换其模型或界面配置。仅修改可见应用名称不能确立独立归属。

## 决策

云枢在获取单实例锁前使用产品专属的打包应用身份和浏览器目录。对外打开协议为 `yunshu`；可选公开终端命令也为 `yunshu`；通用 `dsh` 命令和协议均不归其所有。打包拒绝精确使用上游应用 ID，不会静默发布另一个共用注册身份的安装程序。

Desktop 在既有数据主目录下使用独立配置根。其 profile、主目录 patch、旧设置导入、热重载和内置插件管理命令统一使用此根。仅隔离 profile 路径仍会允许共享主目录 patch 替换产品配置。路径和行为由 [Desktop 参考](../../../../apps/desktop/README.zh.md#installation-ownership)说明。

账号和会话存储保留在既有数据主目录。配置隔离不把活跃刷新凭据复制到第二个主目录，不轮转既有会话，也不改写任务历史。新 profile 从安装包中的 bundle 初始化；来源不明的旧覆盖配置和已启用扩展不会自动激活。

## 考虑过的替代方案

**保留共享身份，提供修复启动器。** 启动器能为一次运行选择正确的可执行文件或浏览器目录，但安装注册、URL 路由和 profile 覆盖仍会竞争。它不能确定产品正常运行时的归属。

**自动迁移整个数据主目录。** 复制活跃登录可能形成两个刷新所有者。迁移混合的历史存储还需要来源和一致性规则，配置修复不能自行推断。业务数据保留原位可以维持既有账号和任务路径，也不冒称完成了全部数据迁移。

**整体复制旧 Desktop profile。** 该 profile 可能包含引发冲突的外来配置。只有单独验证归属的产品偏好可以迁移；整个旧激活树不是权威的云枢来源。

## 后果

云枢与上游 Harness 安装分别拥有独立的应用和配置。既有业务数据仍可按设计共用同一数据主目录，因此此决策不代表业务数据完全隔离。[升级指南](../../../../docs/upgrade-guide/v0.2.1-alpha.2/yunshu-product-isolation/guide.zh.md)说明用户和发布操作人员需要执行的步骤。

应用 ID 变化需要实际验收已安装升级、共存以及卸载时保留另一产品的数据。源码测试或打包成功不能证明这些结果。配置测试必须通过正常 Loader 流程验证冲突的旧 profile 和主目录 patch，同时保持既有账号和任务数据不变。
