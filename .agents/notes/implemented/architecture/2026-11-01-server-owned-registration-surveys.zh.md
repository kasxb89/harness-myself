# Agent Note: Bind registration surveys to server-owned enrollment

Status: implemented

[English](2026-11-01-server-owned-registration-surveys.md) | 中文

## 问题

本机首次登录可能属于老账号或另一台设备。把它视为注册证据会误向老用户索取新用户信息，也可能把迟到答案关联给错误账号。放在登录页内的表单还会在成功登录回聊天时卸载。

## 决策

服务器在真实新手机号注册事务中创建问卷资格。认证账号变化后，客户端读取当前用户状态，只为确认待填写的用户打开全局弹窗。已提交的问卷保持关闭。用户可明确稍后填写，并从余额页继续，不阻挡正常产品使用。

Host 将读写绑定当前认证归属。客户端归属字段用于防止账号切换，不作为上游用户标识。提交回执丢失后读取权威状态；未核对的答案保持锁定直到显式确认，但用户可关闭并重新打开弹窗。问卷失败不会撤销登录，也不会自动重写答案。[Host 参考](../../../../packages/host/credits-index/README.zh.md)与[客户端参考](../../../../packages/client/ui-credits/README.zh.md)负责接口和交互细节。

## 考虑过的替代方案

**把本机首次登录当作新注册。** 本地状态无法证明账号历史、MFA 完成情况或另一台设备的注册。

**填写后才能使用产品。** 问卷或网络故障会把已完成登录变成产品访问失败。明确延期保留使用能力及后续填写入口。

**只把答案存在客户端设置。** 本地设备状态会丢失登记记录，另一台设备也会再次询问已提交问卷。

## 影响

新用户可以多选产品场景并补充选填备注，管理员收到与账号绑定的登记记录。旧 API 没有问卷能力时，登录体验保持可用。免费样本测试覆盖认证 API 契约、当前归属隔离、稍后完成及构建后的浏览器，不实际发送短信或向生产注册。
