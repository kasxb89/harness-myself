# Agent Note: 真人工程师私有沟通

Status: implemented

[English](2026-11-18-private-human-demand-chat.md) | 中文

## 问题

用户需要发布工作需求，并与真人工程师交换图片和视频。AI Session 带有模型可见日志、生成工具和计费语义，其上传接口要求 Session 身份。复用这些数据会混淆真人消息的接收者，也可能将客户私有文件放入无关的 AI 对话。

## 决定

需求服务独立管理需求、消息、分派、已读游标和私有附件。浏览器的[需求插件](../../../../packages/client/ui-demands/README.zh.md) 展示后台管理的服务档案、实际接单工程师和服务端确认的状态，不添加模型输入或生成操作。现有 [Credits Host](../../../../packages/host/credits-index/README.zh.md) 保留账号凭证和串行续期职责；限定的需求路由捕获用户看到的登录身份，在发送前和返回数据前校验。替换后的账号不接收旧草稿、响应或传输。

服务目录条目描述平台接待方向，不创建员工账号或在线状态。用户选择条目后，需求先进入待分配队列，再由管理员指派实际工程师；最初的服务名称始终保留。客户档案在关联已有用户前只是后台记录，不授予登录、积分或消息权限。旧客户端和旧后台仍保留直接选择工程师的提交方式。

每次写操作在提交前记录稳定操作标识和不可变正文。回执丢失时保留原操作供恢复，不阻止独立草稿。上传使用有界文件分片、服务端明确偏移和持久分片摘要；媒体访问重新取得精确附件的授权，支持 Range，不向浏览器暴露上游访问能力。后台控制是否接收新需求；人员上架状态变化后，历史需求仍按当前权限访问。

服务档案操作使用独立本地存储空间，避免旧客户端将不支持的新字段与原工程师操作一起判为损坏。新版读取器合并两者，不重写旧正文或旧标识。

## 验证

控制器测试覆盖身份替换、持久未知提交、多草稿恢复、已读游标、上传偏移与验收核对。Host 测试覆盖路由和 JSON 白名单、账号校验、取消、授权内容地址及 Range 响应。装配后的浏览器场景验证目录、私有聊天和媒体控件；显式启用的本机 Go 合成数据服务联测真实后台、Host 和浏览器，不使用客户凭证或生产数据。

## 考虑过的替代方案

**复用 AI 聊天 Session 和附件存储。** 真人沟通需要独立接收者、权限和处理状态，不能进入模型上下文或生成统计，因此不采用。

**把产品访问令牌交给浏览器。** 现有 Host 已负责令牌续期、退出和跨账号校验，再增加凭证拥有者会扩大暴露面并引入竞态，因此不采用。

**为失答提交换新标识重试。** 传输失败不能证明服务器拒绝了原操作。原操作重放和偏移查询可恢复已有结果并避免重复，因此不采用。

## 影响

- 本地操作记录必须在发送前可用；存储失败只停止对应操作，不阻断其他产品功能。
- 应用重启后，中断上传需要重新选择原文件，并匹配元数据与已记录分片摘要。
- 人员、分派、私有存储和管理依赖独立后台业务，产品既有登录机制保持不变。
