# Agent Note: SkillHub 保留隔离模式并发布可加载的技能元数据

Status: implemented

[English](2026-10-18-skillhub-windows-encoding.md) | 中文

## 问题

Windows 用户看到 SkillHub 推荐加载失败，标签也脱离主内容。Python 的 `-I` 会忽略 `PYTHONIOENCODING`，因此现有环境变量设置无法保证含中文或 emoji 的 Windows 管道输出使用 UTF-8。标签的外边距还覆盖了页面自动水平居中的外边距。

官方 `@clawhub_ivangdavila/writing` 技能安装后包含 `name: Writing`。全局 `isSkillName` 规则拒绝大写名称，因此下载成功后，技能仍可能不出现在会话目录中。

## 决策

Host 保留未修改的官方 CLI 和 Python 隔离模式，并通过 `-I -X utf8` 显式启用 UTF-8。统一的居中内容容器让标题、标签、搜索和结果对齐。

经用户授权，安装在发布前仅将 YAML `name` 标量转为小写，例如将 `Writing` 转为 `writing`，再应用现有全局名称规则。按源文本区间替换，保留其余元数据、注释和正文字节。商店保留官方显示名称和安装坐标。

## 备选方案

**依赖 `PYTHONIOENCODING`。** 否决，因为隔离模式下的 Python 会忽略它。显式配置解释器既保留隔离，也无需依赖机器的 ANSI 编码。

**放宽全局名称规则或自行构造替代名称。** 否决，因为本集成仅需规范大小写。使用 slug 替代、替换空格或转写中文都会引入无关的命名行为。

**重新序列化整个 YAML 文档。** 否决，因为重写无关元数据、注释或格式超出了已获授权的适配范围。

## 后果

转小写后仍非法的名称、缺少必需前置元数据字段，以及需要改大小写的锚定名称，都会在发布前失败。拒绝后一种情况保留了指向该名称的别名语义。已为小写的名称保持字节不变。现有安装暂存、锁文件归属和目录失效机制继续负责发布及即时发现。

## 测试

真实 Python 回归使用旧参数时失败，显式启用 UTF-8 后通过。Loader 组合测试覆盖安装及已加载的目录；元数据回归覆盖内容保留和非法输入拒绝。真实 Chromium 几何检查覆盖 Windows/macOS 样式、浅色/深色主题及 1833、1100、640、360 像素宽度的 16 种组合。

macOS 上的实际检查使用全新官方 CLI 缓存，返回 20 条推荐和 20 条搜索结果，并安装、发现 `writing-polish`。官方 Writing 技能在适配前不出现在目录中；适配后名称为 `writing`，目录能找到它，未改变的 4994 字节正文可以加载。这些检查不包含 Windows 系统上的执行，也不代表完整 GUI/Web 套件的结果。
