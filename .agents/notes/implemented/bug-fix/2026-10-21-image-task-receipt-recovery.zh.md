# Agent Note: 图片等待中断后保留任务回执

Status: implemented

[English](2026-10-21-image-task-receipt-recovery.md) | 中文

## Problem

本地图片超时或取消不能证明服务商是否已受理、完成或计费。丢失已受理的任务编号会阻止安全恢复；把停止等待当作远端任务取消，则可能允许重复付费提交。

## Decision

Credits Host 负责一次付费提交及其回执。它在依赖操作前保存配置后端的指纹、相对路由、模型和已有请求或任务编号。最终结算也会原子保存最新回执，补偿此前中断的独立写入。恢复必须校验账号、聊天、工作区和精确操作归属；每次查询和保存产物都再次核对发起账号。恢复只读取原任务并下载产物，不再次 POST 生成。

提交期限、单次查询期限与任务整体期限分别配置。提交前失败可以安全停止。已发出但结果未确认的请求保留为未知；已受理任务的查询或下载停止时保留为待确认。只有明确拒绝或服务商任务明确失败才能确认失败。本地取消不能证明远端取消。同一聊天中的未确认面板任务会阻止建立另一面板计划，重载后保护仍然有效。

创作私有 JSON 保持原版本，接受可选回执字段。无回执的旧记录仍可读取，并保留未知提交的防重提保护。Session 事件格式不变。查询恢复只复用原操作拥有且逐字节一致的产物；旧文件丢失时可以重新下载，不覆盖原文件。

## Alternatives considered

仅延长提交期限无法恢复重启、取消和查询失败。超时后重发可能重复执行和计费。按相近时间匹配任务不能确定精确回执或安全重试。自动释放旧未知记录会在缺少回执证据时丢弃保护。

## Consequences

临时 GET 失败的重试次数和任务总期限都有上限。稍后继续需要查询保留的原任务。没有任务编号的记录需要核对原请求及计费；客户端不能凭空生成可恢复的编号，也不能保证服务商已停止。回执不包含持久化凭据、原始服务商响应或任意查询 URL。
